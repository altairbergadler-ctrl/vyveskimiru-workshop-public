# Работа с общим репозиторием Мастерской

Начинай с README.md и docs/SNAPSHOT.md. Каталоги сервисов независимы;
сохраняй существующие границы запуска, данные и авторизацию.
Перед правкой компонента читай его AGENTS.md, CHECKPOINT.md и архитектуру,
если эти файлы присутствуют. Исторические release notes не заменяют проверку VPS.

- `services/workshop` — один backend/PWA и модуль заказов; Google Таблица —
  единственный бизнес-источник. Правила этого компонента сохраняются.
- `services/signage` — отдельный сервис с собственными историей и входом.
- `services/stamp` — отдельный сервис документов; настоящие печати и подписи
  хранятся в закрытых данных, а не в исходниках.
- `apps/fonts` и `apps/calculator` включают необходимые статические `dist/`;
  не исключай их из Git общим правилом для всех сборок.
- `ops/` содержит действующие серверные программы и unit-файлы.
  Не запускай расписания, отправку сообщений, резервное копирование или очистку
  только ради проверки кода.
- Не добавляй секреты, записи заказов, базы, истории генераций и резервные копии.
- Выполняй проверки из каталога изменённого компонента. Для основного сервера
  обязательна `npm run check`; не используй боевую Google Таблицу как тестовую.
- Изменение исходников в GitHub не означает установку на VPS. Публикация на сервер
  выполняется отдельным штатным процессом с проверкой актуальной версии и копией.
