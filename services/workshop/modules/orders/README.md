# Модуль заказов · Мастерская

CRM временно отключена с сохранением данных 6 сентября 2026. Ссылка на неё
убрана из меню; создание клиентов и работа с контактами в заказах продолжаются.
Архив CRM находится в соседнем репозитории `workshop-crm-2026-09-05` и резервных копиях.

Общая актуальная карта всех приложений, их источников данных и связей:
[Архитектура Мастерской](../../ARCHITECTURE.md).
Результат объединения: [отчёт от 6 сентября 2026](../../docs/RELEASE_2026-09-06_UNIFIED_WORKSHOP.md).

Модуль общего приложения с канбаном заказов для `https://vm-app.ru/kanban/`.
История исходного репозитория сохранена в общей Git-истории. Самостоятельный сервер
остановлен; запуск и развёртывание выполняются только из корня общего проекта.
Источник данных: существующая Google-таблица `Ucheta_naruzhnaya_reklama (1)`.

Производственные столбцы соответствуют справочнику статусов на листе «Настройки».
Одна карточка — один номер заказа. Подробности объединяют листы «Заказы»,
«Позиции», «Клиенты», «Производство», «Платежи» и «Расходы» по исходным ключам.
Свободные расходы без номера заказа не распределяются между заказами.
Отдельный этап «Монтаж» не включается в готовность производства.

Меню по умолчанию свёрнуто в полосу кнопок. На компьютере раскрытие сохраняется
в браузере, а на телефоне каждый вход и возврат на страницу начинается со
свёрнутого меню.
Полное меню повторяет оболочку Мастерской: дашборд, производство, склад,
канбан, операции и денежный поток. На телефоне компактное состояние
оставляет быстрые переходы к дашборду и канбану, а раскрытое показывает
все разделы.
Сводка собрана в компактной шапке. Заказы распределяются без дублей между
производственными столбцами, горизонтальной лентой монтажей снизу и узким
архивом справа. Поиск и фильтр менеджера работают во всех трёх зонах.
На телефоне архив доступен ниже монтажей внутри прокручиваемого рабочего поля.

Кнопка «Создать заказ» в шапке открывает секционную форму в общей визуальной
системе Мастерской: тёмная шапка, зелёный акцент, тёплый фон и светлые группы
полей. В ней доступны название, дата, клиент, менеджер, ручная
сумма/себестоимость, сроки и комментарий. Клиент и менеджер
выбираются из справочников таблицы. Новый заказ получает номер автоматически
и статус «Расчёт / КП»; после сохранения фильтры сбрасываются и открывается
его карточка. При пустой доске справочники также загружаются из источника.
Расчётные суммы, долг, даты и служебные формулы не вводятся вручную.

Под выбором клиента есть действие «Создать нового клиента». Оно открывает
такую же секционную карточку поверх формы заказа: название или ФИО, тип, контактное лицо,
телефон, email, реквизиты, источник, дату добавления и комментарий. После записи
новый клиент автоматически выбирается в заказе, а уже заполненный черновик
заказа остаётся на месте. Заполняются только ручные B:J листа «Клиенты»;
формульный ID и итоговые K:P сохраняются. При одном совпадении имени с учётом
регистра и «е/ё» выбирается существующий клиент; дубликат не создаётся.

Создание занимает свободную подготовленную строку листа «Заказы», сохраняя
формулы и оформление. Если подготовленные строки закончились, приложение
сообщает об этом до записи. Приватный журнал в
`/var/lib/orders-kanban/creation` сохраняется между выпусками и защищает от
повторного создания одним запросом. Путь задаётся `ORDER_CREATE_DIR`, локально
по умолчанию используется `work/creation`. После неопределённого ответа форма
позволяет проверить тот же запрос; повторная запись автоматически не делается.
Для клиента действует такой же отдельный журнал в
`/var/lib/orders-kanban/client-creation` (`CLIENT_CREATE_DIR`). После
подтверждения в нём остаётся только минимум для безопасной проверки запроса.

Во вкладке «Состав» менеджер видит позиции заказа и добавляет новые через
шаблоны «Уличная вывеска», «Неоновая вывеска», «Плоттерная резка» или
свободную форму нетиповой работы. Типовые формы показывают только подходящие
параметры, а описание для листа «Позиции» собирается из выбранных материалов,
цвета, подсветки, крепления и уточнений. Цена и себестоимость необязательны;
итоговые суммы остаются формулами таблицы. Существующие позиции по-прежнему
редактируются по отдельным полям.

Для уличной и неоновой вывески приложение читает текущие этапы листа
«Маршруты» и создаёт подготовленные строки листа «Производство». Этап с точным
названием «Монтаж» не переносится: выезд согласовывается отдельно. Внутренний
этап «Монтаж неона на основание» сохраняется. Для плоттерной и нетиповой работы
маршрут не придумывается без настройки источника. Добавление запрещено после
готовности, передачи на монтаж, сдачи или отмены заказа. Журнал заявок в
`/var/lib/orders-kanban/position-creation` защищает от повторной записи при
потере ответа и включён в резервную копию каждого выпуска.

В ленте монтажей находятся старые заказы со статусом «Монтаж» и готовые заказы
с неотменённой записью монтажа. Ранний заказ с заранее назначенным выездом
остаётся в производстве до готовности. Завершённый выезд остаётся в ленте,
пока пользователь не отправит заказ в архив. Все подробности и файлы доступны
через карточку в любой зоне.

Перенос в архив или кнопка «В архив» доступны из «Готов к выдаче» и «Монтаж».
Один запрос ставит заказу существующий статус «Сдан», активным записям монтажа —
«Выполнен». Отменённые и выполненные монтажи не переписываются; финансовые и
старые производственные строки не меняются. Проверяется версия каждого монтажа
и неизменность полного набора связанных записей. Обычные маршруты смены статуса
и редактирования не позволяют обойти это действие. Архив также показывает
ранее отменённые заказы. Сданный заказ можно вернуть на доску, сохранив отметки
выполненных монтажей; для отменённого заказа пользователь явно выбирает статус.

При переносе изменяется статус найденного заказа; при первом переходе в
«Готов к выдаче» записывается фактическая дата готовности. Перед записью
проверяются актуальный номер, статус и справочник; после записи результат
перечитывается. Если статус уже изменён другим пользователем, возвращается
конфликт, доска обновляется. Google Sheets не предоставляет транзакционную
проверку значения при записи: избегайте сортировки/перестановки строк таблицы
одновременно с переносом карточек. Ошибки проверки не вызывают повторную запись.

Доска обновляется автоматически. Офлайн-запись не поддерживается. Редактор
показывает ручные поля заказа, контактов, позиций, производственных этапов,
платежей и расходов. Расчётные суммы защищены: для суммы/себестоимости заказа
используются существующие ручные значения, для долга — исходные платежи.
Номер заказа остаётся ключом связей. Переименование клиента обновляет ссылки
на него в заказах. Редактирование проверяет версию исходного листа и сохраняет
формулы в соседних ячейках. Открытый черновик не заменяется автообновлением.

Финансовые правки проходят через существующий API финансов, с проверкой
соответствия записи таблице и отсутствия ожидающей синхронизации. Прямой записи
в финансовые ячейки нет. Общая очередь защищает от параллельных правок канбана;
Google Sheets и старый финансовый API не имеют атомарного compare-and-set для
независимой одновременной правки в другой программе. Неподтверждённая запись не
повторяется автоматически; пользователь получает явное сообщение.

## Готовность и монтаж

«Готов к выдаче» завершает изготовление, остаётся видимым на доске и исключается
из производственной просрочки и активного счётчика. Старые «Монтаж», «Сдан» и
«Отменён» также исключаются из этих показателей. Производственные отметки
сами не переводят заказ в готовность; перенос не проставляет их автоматически.

На листе «Заказы» добавлены U «Фактическая дата готовности» и V «Срок сдачи вручную».
J сохраняет отдельный согласованный срок, при пустом V берёт желаемую дату I.
Известный ручной срок J10 сохранён в V10. Формула R учитывает готовность.
Исходная копия формул перед миграцией находится в приватном каталоге backups VPS.

Лист «Монтажи» хранит отдельные связанные услуги: ID, номер заказа, статус,
дату, время, контакт, телефон, адрес, комментарий и исполнителя. Статусы:
«На согласовании», «Назначен», «Выполнен», «Отменён». Новая запись создаётся
только пользователем, телефон подставляется из контакта клиента и допускает
отдельный контакт объекта. Старые производственные строки «Монтаж» сохраняются.

## Файлы заказов

JPG, PNG, WebP, GIF и PDF хранятся приватно вне выпусков, в
`/opt/finance-pwa/shared/data/orders/media` на VPS (`/data/orders/media` в контейнере). Файлы и манифест
записываются атомарно с fsync; обложка и связи переживают перезапуск и деплой.
Каждое чтение, скачивание, назначение обложки и удаление требует действующий
вход. PDF отдаётся как скачиваемый файл, безопасные изображения — как превью.
Обложка использует оригинал изображения; отдельного уменьшенного файла пока нет.

Лимиты: 12 МиБ на файл, 60 МиБ и 30 активных файлов на заказ, 2 ГиБ физического
хранилища. Удаление мягкое: файл исчезает из приложения, байты сохраняются для
восстановления и продолжают учитываться в физической квоте. До 1000 сохранённых
записей файлов. Файлы включены в общее ежедневное резервирование Мастерской.
Полные копии до и после объединения также сохранены на Windows.

## Запуск и проверка

Из корня `finance-pwa-2026-08-30`:

```sh
npm test
npm run lint
npm run build
```

Для запуска используется общий `server/index.mjs`. Рабочий контейнер слушает
порт 3000, опубликованный только на `127.0.0.1:18100`. Конфигурация и Google-ключ
передаются общему серверу извне репозитория. Старые конфигурации, checkpoint и deploy
внутри этого модуля сохранены как история, применять их к рабочему серверу нельзя.

Каждый запрос к данным требует действующую сессию общего приложения.
Вход проверяется внутри процесса, без HTTP-зависимости от соседнего сервиса.
Ответы с данными имеют `Cache-Control: no-store, private`, изменения проверяют Origin.

## Развёртывание

Общее руководство: [README](../../README.md), установщик
[`deploy/install-workshop.sh`](../../deploy/install-workshop.sh).
Все разделы выпускаются вместе; контрольная точка содержит данные и инструкции отката.

Важна совместимость с существующим service worker финансов: он должен
пропускать `/kanban` и `/kanban/*`, а навигацию сохранять под `/` только для
корневой страницы. Совместимая правка готовится отдельным коммитом, без изменений
финансовых функций. Детали текущего выпуска записаны в общем [CHECKPOINT.md](../../CHECKPOINT.md).
