# Формат проекта и расчёт

Единицы: сантиметры в плоскости установки; координаты изображения — пиксели исходного ориентированного фото, начало слева сверху, X вправо, Y вниз. Не меняй фото после разметки. У `rectangle` начало плоскости — первый угол эталона, X вдоль его верхней стороны, Y к нижней стороне. У `frontoparallel` оси совпадают с осями изображения.

Масштаб и смещение просмотра фотографии не являются калибровкой и не входят
в JSON проекта. Даже при zoom/pan точки сохраняются в пикселях исходного фото.
Вид может восстанавливаться из отдельного локального черновика браузера.

## Версия 2: общая сцена и изделия

Новые проекты редактора используют `version:2`. Старые проекты версии 1
открываются как объёмные буквы; их исходные параметры сохраняются.
В версии 2 общая сцена остаётся на верхнем уровне: `image`, `calibration`,
`target_polygon_px`, `generation`, `measurements`, `ruler`, `checks`,
`spec_source` и `assumptions`. Отдельного вложенного поля `scene` нет.

`products` — список изделий, `active_product_id` — ID выбранного изделия.
Этот выпуск принимает ровно одно изделие; несколько объектов, неизвестный
тип или неподдерживаемая версия модуля дают явную ошибку.
Каждое изделие содержит:

- `id` и `type`: `channel_letters`, `plaque` или `neon`.
- `module_version:1`: версия структуры и поведения модуля.
- `template_id` и `template_version`: происхождение стартовых настроек.
  Версия шаблона — целое число от 1 до 1 000 000; сохранённые `params`
  являются источником истины и не заменяются новым содержимым каталога.
- `placement`: центр в пикселях исходника, ширина/высота в сантиметрах
  и поворот в плоскости, как в примере версии 1 ниже.
- `params`: параметры конкретной конструкции. Толщина таблички/неона,
  радиус углов и отступы задаются в миллиметрах.
- Необязательный `artwork`: `{name, mime_type:"image/png", data_url,
  width_px, height_px, source:"text"|"uploaded"}`. Он хранит самостоятельный
  PNG изделия; для создания макета таблички или неона сервер требует его.

Возможные старые поля верхнего уровня `sign` и `placement` служат только
совместимости. В проекте версии 2 параметры и размещение берутся из
канонического активного изделия. Фотография по-прежнему передаётся отдельно
от JSON; PNG изделия, если есть, включается в проект. Максимум PNG — 2 МиБ,
4096 пикселей по стороне и 16 мегапикселей; проект версии 2 ограничен
4 МиБ UTF-8 в сохранённом представлении. Для неона нужен прозрачный фон
вокруг контура. PNG вписывается с сохранением пропорций с учётом полей
таблички либо отступа подложки неона.

`generation.engine` выбирает обработку:

| Значение | Назначение |
| --- | --- |
| `codex` | Прежняя ИИ-визуализация объёмных букв |
| `composite` | Табличка/неон из точного PNG, без внешней генерации |
| `codex_composite` | Один ИИ-запрос подготовки фона, затем точное наложение таблички/неона |

Без `engine` используется стандартный режим выбранного изделия. Для новых
модулей ночь не включает автоматически подсветку таблички или выключенного
неона; режим свечения задаётся параметрами изделия. Защита пикселей вне
разрешённой зоны обязательна для всех режимов. Автоматического повтора нет.

Состав модулей, каталог и дальнейшее расширение описаны в
[PRODUCTS.md](../docs/PRODUCTS.md); ограничения отправки, движки и артефакты —
в [HTTP API](../docs/API.md).

## Версия 1: прежний проект объёмных букв

Следующие примеры и дополнительные поля `sign` относятся к версии 1.
В версии 2 эти параметры находятся в `products[].params`, а размещение —
в `products[].placement`; общие поля сцены и калибровки остаются прежними.

Минимальный пример версии 1 для фронтального вида:

```json
{
  "version": 1,
  "image": {"name": "facade.png", "width_px": 1600, "height_px": 1000},
  "calibration": {
    "mode": "frontoparallel",
    "plane": "передняя плоскость фасада",
    "frontoparallel_assumed": true,
    "image_points": [[200, 700], [680, 700]],
    "length_cm": 120
  },
  "placement": {
    "center_px": [800, 350],
    "width_cm": 220,
    "height_cm": 45,
    "rotation_deg": 0
  },
  "sign": {
    "text": "КОФЕ",
    "font_family": "название из ТЗ",
    "font_status": "требуется сверить начертание",
    "size_basis": "габарит всей композиции",
    "depth_cm": 5,
    "front_color": "#fff3dc",
    "side_color": "#292f30",
    "brief": "Молочный акрил, тёплый контражур",
    "source_dimensions": "2200 × 450 мм; глубина 50 мм"
  },
  "target_polygon_px": [[250, 180], [1350, 180], [1350, 550], [250, 550]],
  "measurements": [{"name": "панель", "image_points": [[100, 180], [1500, 180]], "same_plane": true}],
  "checks": [{"name": "вторая панель", "image_points": [[100, 550], [900, 550]], "length_cm": 200, "same_plane": true}],
  "spec_source": "Файл ТЗ, страница/раздел либо сообщение пользователя",
  "assumptions": ["Фасад считается плоским, перспектива слабая"]
}
```

Для перспективного снимка замени `calibration`:

```json
{
  "mode": "rectangle",
  "plane": "наружная плоскость панели",
  "image_points": [[210, 170], [1400, 260], [1360, 720], [230, 830]],
  "width_cm": 400,
  "height_cm": 200
}
```

Оба физических размера обязательны. Координаты выбраны исключительно для примера — не используй их с реальным фото. Положительный поворот направлен по часовой стрелке в плоскости. `placement`, `target_polygon_px`, `measurements`, `checks`, `spec_source`, `assumptions` опциональны. Для измерений в иной плоскости укажи `same_plane:false`; расчёт вернёт `null`, а не выдуманное число. Проверочные отрезки должны быть независимыми от калибровочных размеров. Не добавляй вымышленные проверки ради прохождения порога.

Вызов без зависимостей (Node.js):

```text
node <skill>/scripts/project.cjs project.json output/letters-v1
node <skill>/scripts/project.cjs project.json output/letters-v2 oriented-photo.png
node <skill>/scripts/test-geometry.cjs
```

CLI создаёт `report.json` и `geometry.svg`; если файл результата уже существует, выбери новый каталог версии. Вызов без фото создаёт прозрачную схему с исходными размерами кадра. Для встраивания фото CLI принимает только PNG и проверяет его пиксельные размеры. JPEG/WebP можно использовать в локальном редакторе. EXIF-ориентация исходника должна быть уже применена; не конвертируй с растяжением, поворотом или кадрированием после разметки.

`report.calibration.worldToImage` и `imageToWorld` — матрицы 3×3 построчно. Для точки `[x,y]`: `u=(h0*x+h1*y+h2)/(h6*x+h7*y+h8)`, аналогично `v`. `report.placement.polygon_px` — четыре вершины габарита. `fits_target` появляется, если есть отмеченная область. `measurements.length_cm` — оценка отрезка. `checks.residual_pct` — знаковое расхождение с контрольным размером. `check_tolerance_pct` по умолчанию 5 — лишь порог сообщения о расхождении, не доказанная точность измерения.

За пределами эталонного прямоугольника используется продолжение той же плоскости. Скрипт предупреждает об этом, о выходе габарита из кадра/области и об отсутствии независимой проверки. Скрипт не оценивает дисторсию, не подтверждает плоскостность сцены и не восстанавливает глубину. Не округляй внутренние координаты; в ответе обычно достаточно 0,1–1 см со знаком «≈», сообразно качеству данных.

Основа преобразования: [официальное объяснение плоской гомографии OpenCV](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html). Четырёхугольник изображения сопоставляется прямоугольнику **с известными метрическими размерами**. Код рассчитывает матрицу с нормализацией координат и проверяет вырожденные конфигурации.

## Интерактивная линейка (необязательное расширение версии 1)

```json
{"ruler":{"image_points":[[100,180],[500,180],[500,380]],"same_plane":true}}
```

`ruler.image_points` — последовательность от 0 до 256 точек в пикселях
исходного фото. Каждая точка содержит два конечных числа внутри кадра.
Ноль или одна точка допустимы как незавершённый замер. Старые проекты без
`ruler` продолжают работать; прежние двухточечные `measurements` сохраняются.

`same_plane:true` обозначает допущение пользователя, что вся цепочка лежит
в плоскости эталона. Для другой плоскости используйте `false`: сантиметры
не рассчитываются. Отчёт `report.ruler` содержит длины сегментов
`segment_lengths_cm`, накопленные длины `cumulative_lengths_cm`, сумму
`total_cm` и преобразованные координаты `points_cm`. Расчёт выполняется в
плоскости после обратного преобразования перспективы. Линейка попадает в
техническую схему, но не рисуется в изображениях, передаваемых генератору.

## Параметры ИИ-макета (необязательное расширение версии 1)

```json
{
  "generation": {
    "lighting": "night",
    "edit_polygon_px": [[250,180],[1350,180],[1350,550],[250,550]],
    "geometry_lock": true,
    "background_cleanup": "inside_edit_zone_only",
    "night_illumination_required": true
  }
}
```

`lighting`: `original`, `sunny`, `cloudy`, `night`. `edit_polygon_px` — четыре угла разрешённой зоны замены в пикселях исходника; при отсутствии используется `target_polygon_px`. Она должна включать всю надпись, тени/свет и старую вывеску для удаления. `geometry_lock` и ночная подсветка обязательны: значения `false` во внешнем JSON не отключают защиту сервера. Размеры/перспектива заново вычисляются сервером через `geometry.js`, клиентский отчёт не считается доверенным. Фото и данные авторизации в JSON проекта не включаются.

## Многострочные надписи

Явные переносы `\n` внутри `sign.text` задают строки сверху вниз. Например, `"ЦВЕТЫ\nИ БУКЕТЫ"`. `sign.line_gap_cm` — чистый вертикальный промежуток между рамками строк в сантиметрах, по умолчанию 5. `sign.text_align`: `left`, `center` или `right`, по умолчанию `center`. `placement.width_cm` и `placement.height_cm` всегда описывают общую композицию со всеми строками и промежутками. Размер букв для строк общий, пропорции сохраняются; узкие строки выравниваются относительно общей рамки. Переносы передаются в ИИ-задание явно, а не рассчитываются моделью по длине текста.

Редактор сохраняет `sign.preview_line_metrics`: измеренные браузером ширины и границы каждой строки условного шрифта Arial при размере 100 px. Они позволяют одинаково строить расположение строк в браузере, серверном отчёте и SVG. Не выдумывай эти значения по числу букв. Старые проекты без метрик сохраняют рассчитанную общую рамку; открытие в редакторе измеряет строки и добавляет метрики при сохранении. Для перспективного SVG текст проецируется треугольной сеткой, фотография не преобразуется. Точное начертание по ТЗ остаётся отдельной проверкой.

## Параметр начертания и пакет CorelDRAW

`sign.font_bold` — необязательное логическое поле версии 1. Для интерфейса
CorelDRAW отсутствие поля означает `true`; явное `false` снимает Bold.
`sign.font_family` хранит имя шрифта из ТЗ. Браузерный эскиз остаётся условным
Arial, а Windows-экспорт требует установленного указанного шрифта.

Из проекта пакет CorelDRAW получает `sign.text`, `placement.width_cm`,
`placement.height_cm`, `sign.line_gap_cm`, `sign.text_align`, `sign.font_family`,
`sign.font_bold` и `sign.front_color`. API принимает их отдельным плоским объектом
без префиксов `sign`/`placement`; фото и перспективные координаты не передаются.
В CDR создаётся плоская лицевая композиция 1:1. Заданные ширина/высота — рамка
для пропорционального вписывания, не приказ независимо растянуть буквы по
осям. [Полный формат и Windows-процесс](../docs/CORELDRAW.md).

## Плёнка на акриле и лицевая подсветка

```json
{
  "sign": {
    "front_color": "#DBFFE4",
    "side_color": "#E70D65",
    "face_material": {
      "type": "film_on_acrylic",
      "brand": "ORACAL",
      "series": "",
      "color_code": "",
      "finish": "unspecified",
      "acrylic": "unspecified",
      "led_temperature_k": null,
      "day_lighting": "off"
    }
  }
}
```

Этот пример фиксирует способ изготовления, но не конкретную серию или цвет из каталога. `series` и `color_code` — строки; ведущие нули сохраняются. Пустое значение означает «не указано». `finish`: `unspecified`, `matte`, `satin`, `gloss`. `acrylic`: `unspecified`, `opal` (молочный), `clear` (прозрачный). `led_temperature_k`: `null` либо число 1000–20000 К; диапазон является проверкой ввода, не рекомендацией оборудования. Без температуры генератор использует явно условный нейтральный белый свет. `day_lighting`: `off` или `on`; ночью лицевая подсветка обязательна.

`front_color` — приблизительный экранный образец плёнки, `side_color` — отдельный цвет бортов. Сам по себе введённый код серии не устанавливает соответствие каталогу: приложение не загружает веер и не заменяет HEX автоматически. Не приписывай произвольному HEX артикул производителя. Значение `type:"custom"` и отсутствие `face_material` в старом проекте сохраняют прежний режим материалов по ТЗ.

Генератор получает `color-reference.png` третьим изображением: нейтральная карточка точных экранных образцов, без измерений светопропускания. В `audit.json` сохраняются выбранный материал, цвета и признак `color_accuracy:"approximate_not_colorimetrically_verified"`. Это означает, что защита кадра проверена отдельно от соответствия оттенка реальной плёнке.
# Перспектива области установки · версия 1

Необязательное поле `facade` включает новую модель только явно. Если поле
отсутствует или `enabled:false`, прежние калибровка и экспорт не меняются.

```json
{"version":1,"enabled":true,"lens_enabled":false,"edge_points":[null,null,null,null],"grid_visible":true,"grid_step_cm":50,"snap_elements":true,"snap_grid":true}
```

Поле хранится на верхнем уровне проекта, рядом с `calibration` и
`target_polygon_px`. `edge_points` — дополнительные точки реальных прямых
краёв в порядке верх, право, низ, лево, в исходных ориентированных пикселях.
Противоположные края области должны быть параллельны в реальности.
Точки по четырём углам сами по себе не определяют искажение объектива.

Ширина и высота области — только информационные значения
`report.calibration.zone_info`, вычисляемые из ранее установленного масштаба.
Они не записываются обратно как эталон. Прямоугольный эталон сохраняет
метрические расстояния; оси фасада поворачиваются по верхней границе зоны
без изменения масштаба. Один отрезок сохраняет заданную длину, но задаёт
только приблизительные пропорции плоскости с явным предупреждением.

Геометрический отчёт при включённом режиме содержит JSON-дескрипторы
`worldToImage`, `imageToWorld`, `placement.local_to_image` и
`sign_layout.objects[].local_to_image`:

```json
{"type":"facade_projection_v1","matrix":[1,0,0,0,1,0,0,0,1],"direction":"forward","lens":{"k":0,"cx":600,"cy":380,"scale":1200,"width":1200,"height":760}}
```

`forward`: локальная/мировая точка → гомография в исправленное фото →
обратная модель объектива в исходные пиксели. `inverse`: исходные пиксели →
исправление объектива → уже обратная `matrix`. Делительная модель:
`U=C+(D-C)/(1+k*r_D^2)`, радиус нормирован на длинную сторону фото.
Используется однозначная ветвь без полюсов/перегибов в кадре.

`polygon_px` остаётся четырьмя углами для совместимости;
`boundary_px` и `target_boundary_px` содержат изогнутые границы. Растер и
установочная схема используют полную проекцию, а не четырёхточечное приближение.
`target_world_cm` задаёт фактическую границу для размещения и привязок.
Исходная фотография не выпрямляется и не меняет ракурс.

`generation.edit_region_source:"placement_zone"` с пустым `edit_polygon_px`
использует полную изогнутую границу установки. Явно отмеченная зона замены
остаётся самостоятельным многоугольником в пикселях исходного фото.
Сетка, её шаг и привязки сохраняются как настройки инструмента, но их изменение
не делает существующий результат генерации устаревшим; изменение геометрии
фасада делает.

Новая область по умолчанию включает привязку к сетке; явное сохранённое
`snap_grid:false` сохраняется. Привязки объектов, повёрнутых групп и целого
изделия вычисляются в общих координатах фасада. Alt временно отключает
притяжение, не меняя размеры изделия.

Фотореалистический генератор получает отдельный `facade-grid.png` и модель
камеры с образцами кривых в координатах рабочего изображения. Это технический
референс; линии не добавляются в исходное фото или результат. Опорная сетка
генератора строится независимо от видимости и шага сетки редактора. Точный
растр макета математически следует проекции; результат ИИ внутри разрешённой
области остаётся визуализацией по референсам и не имеет гарантии совпадения
каждого глифа с исходным макетом.


## Зерно исходной фотографии

`generation.photo_match` отсутствует/null для прежнего поведения либо равен
`"source_noise_v1"`. Включённый режим требует `lighting:"original"` и точной
маски: `composite`, `codex_composite` или `codex_two_stage`. Неподдерживаемая
комбинация отклоняется до запуска обработки. В интерфейсе это отдельный выбор
«Цветокоррекция как на фото» в группе освещения.

Поле не влияет на физические параметры, рисунок, калибровку, расположение
или повторное использование нейтрального образца изделия. После установки
выполняется локальная обработка шума по оригинальному снимку. В аудит входит
`photo_match` с версиями, оценками RGB-дисперсии, хешем маски поверхности,
числом изменённых пикселей; вне поверхности изменения от этого этапа равны 0.
