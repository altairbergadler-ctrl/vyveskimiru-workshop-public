# Визуализация рекламной продукции

Единый редактор размещает объёмные буквы, таблички и неоновые вывески на
фотографии по размерам в сантиметрах. Калибровка по эталону, перспектива одной
плоскости, линейка, освещение, черновик и история общие для всех изделий.
Настройки конструкции и стартовые варианты выбираются по виду продукции.

Объёмные буквы используют прежнюю ИИ-визуализацию через подключённую на
сервере подписку ChatGPT / Codex. Таблички и неон переносятся из отдельного
точного PNG-макета с сохранением пропорций и рассчитанной перспективы.
Обычное наложение работает без Codex и не расходует лимит ИИ; при необходимости
можно выбрать подготовку фона с ИИ перед наложением. Экспорт лицевых контуров
в установленный CorelDRAW 2024 на Windows доступен для объёмных букв.

**Рабочий редактор:** [vm-app.ru/signs/](https://vm-app.ru/signs/).
**История:** [сохранённые генерации](https://vm-app.ru/signs/history.html).
**Перенос проекта:** [скачать исходники, документацию и снимок истории](https://vm-app.ru/signs/downloads.html).
Вход — одним паролем, без имени пользователя. Пароль и серверные секреты
передаются отдельно от исходников.

## История выпусков

Выпуск **20261009-vps8** добавил открытие CDR по кнопке через локального
помощника Windows. См. [установку](docs/CORELDRAW.md). Он сохраняет чёрный цвет векторов CDR по умолчанию
(`RGB 0, 0, 0`). Он задаётся для пакета CorelDRAW отдельно от лицевого цвета
вывески на фото. Размеры и геометрия контуров сохраняются. Статус размещения
и результаты проверок — в [TESTING.md](TESTING.md).

Выпуск vps6 исправил разметку эталона:
точки остаются диаметром 12 CSS-пикселей при любом масштабе, подписи — 14 пикселей,
а под кнопкой виден прогресс разметки. Сброс зависшего перемещения возвращает
возможность ставить точки после потери события отпускания средней кнопки.

Выпуск vps5 добавил масштабирование фотографии у курсора,
перемещение средней кнопкой, кнопки «+», «−», «Вписать» и «100%». При 100%
один пиксель исходника равен одному CSS-пикселю; предел — 800%. Масштаб вида
не меняет фото и координаты проекта. Пакет CorelDRAW создаёт на Windows
лицевые кривые 1:1 из шрифта ТЗ; подробности — в [инструкции](docs/CORELDRAW.md).

Линейка из vps4 сохраняется: левый клик добавляет
точку, правый по точке или рядом с ней удаляет её; длины отрезков и сумма
пересчитываются в сантиметрах по калибровке. Esc завершает редактирование,
сохраняя точки; доступны отмена точки и очистка. Линейка сохраняется в проекте
и работает независимо от параметров вывески. При неверной калибровке или другой
плоскости вместо недостоверных сантиметров показывается сообщение.

Страница передачи из vps3 остаётся на `https://vm-app.ru/signs/downloads.html`.
Маршруты, Caddy и основной сайт не меняются. Результаты проверки конкретного
выпуска — в [TESTING.md](TESTING.md); для линейки добавлен `scripts/test-ruler.cjs`.
Фото, проект и текущий вид автоматически сохраняются как локальный черновик
этого браузера и восстанавливаются после обновления страницы. Последний готовый
ИИ-результат загружается из серверной истории без новой генерации. Этот черновик
не синхронизируется между устройствами и не заменяет экспорт проекта.

Приложение запускается парой **`compose.host-proxy.yaml` +
`compose.password.yaml`**. Первый файл задаёт контейнер, данные и loopback-порт,
второй включает вход по паролю и подключает закрытый файл конфигурации.
Существующий Caddy предоставляет HTTPS и маршрут `/signs/`; Basic Auth в
правиле редактора больше не используется. Не запускайте этот выпуск без
второго файла Compose.

Для предыдущего выпуска vps2 на Linux прошли **70 Python-тестов** и проверки геометрии и путей JavaScript.
Проверены вход через браузер, защищённые HTTPS-маршруты и история из **7 заданий**.
Ранее выполнена одна настоящая генерация на исходной фотографии через Codex
на VPS: результат сохранён, визуально просмотрен, а вне зоны замены
подтверждено 0 изменённых пикселей относительно световой основы. Детали,
границы проверки и идентификатор задания — в [TESTING.md](TESTING.md).

## Как устроено приложение

Браузер → Caddy HTTPS → Python-сервер → обработка выбранного изделия →
проверка и сборка результата → история.

Калибровка, эскиз и текстовый PNG работают в браузере. По кнопке сервер
совмещает точный макет таблички/неона с фото (`composite`) либо вызывает Codex
для объёмных букв (`codex`). Выбранная подготовка фона (`codex_composite`)
использует один запрос Codex, после которого новый макет накладывается
программно. Только ИИ-режимы передают фото в OpenAI. Одновременно выполняется
одно задание, без автоматических повторов. API-ключ не используется.

История и исходные фотографии хранятся в томе `signage-editor_data`,
авторизация Codex — отдельно в `signage-editor_codex_home`. Все пользователи,
знающие пароль этого экземпляра, видят общую историю и используют одну
подключённую подписку. Отдельных аккаунтов клиентов и очереди заданий нет.

Фотография сохраняет исходную геометрию. Режим дня или ночи меняет цвет и
яркость световой основы; за пределами отмеченной зоны итог совпадает с ней.
При выбранном ИИ-режиме внутри зоны может восстанавливаться фон; его детали
проверяют визуально. У табличек и неона новый текст переносится из точного
PNG, а у объёмных букв форма и текст ИИ-результата требуют визуальной сверки.

Размеры надёжны только в пределах допущений калибровки. Эталон на другой
глубине даёт приблизительный концепт. HEX и код ORACAL не образуют проверенную
цветовую модель: макет не заменяет обмер для производства и физическую
цветопробу плёнки на акриле.

## Установка на новый сервер

Ниже — основной вариант со входом одним паролем и каталогом `/signs/`.
Для действующего `vm-app.ru` используйте [DEPLOYMENT.md](DEPLOYMENT.md):
на нём уже работают Caddy и другие сервисы.

### 1. Подготовьте окружение

Нужны Linux, Docker Engine с плагином Compose, Caddy на хосте и Python 3.10+
на хосте для создания конфигурации входа. ИИ-генерация выполняется сервисом
OpenAI; обычное наложение PNG — самим сервером. Видеокарта на VPS не требуется.
Домен должен указывать на сервер,
а Caddy — обслуживать его по HTTPS. Установку и запуск Docker/Caddy выполняйте
по инструкциям для выбранной ОС; этот проект не заменяет конфигурацию
существующего веб-сервера.

Распакуйте исходники в отдельный каталог выпуска, например:

```text
/opt/signage-editor/releases/20261010-products-v1/vps-project
```

Не распаковывайте проект, историю или секреты в публичный каталог основного
сайта. Все последующие команды выполняются на новом VPS из корня проекта.

### 2. Создайте файл доступа

От имени администратора:

```sh
umask 077
install -d -m 700 /opt/signage-editor/private
python3 scripts/editor_auth.py create \
  --output /opt/signage-editor/private/editor-auth.json --cookie-path /signs/
chown 10001:10001 /opt/signage-editor/private/editor-auth.json
chmod 0400 /opt/signage-editor/private/editor-auth.json
```

Команда интерактивно запросит пароль дважды. Она использует стандартную
библиотеку Python и создаёт новый файл; существующий не перезаписывается.
Проверьте успешное завершение каждого шага. Родительский каталог принадлежит
root и имеет права `0700`; сам файл — UID/GID `10001:10001` с правами `0400`.
Так Docker может подключить закрытый файл, а непривилегированный пользователь
приложения — прочитать его. Для смены пароля уже установленного редактора
следуйте отдельной процедуре в [DEPLOYMENT.md](DEPLOYMENT.md).

### 3. Настройте выпуск

Создайте закрытый файл `.env` с правами `0600`:

```dotenv
DOMAIN=example.com
APP_VERSION=20261010-products-v1
CODEX_VERSION=0.162.0-alpha.2
EDITOR_AUTH_HOST_FILE=/opt/signage-editor/private/editor-auth.json
```

Замените `example.com` своим доменом. В `DOMAIN` указывается только имя домена:
без протокола, порта и `/signs/`. Путь каталога задают конфигурация cookie и
Caddy. Пароль в `.env` не записывают. Не обновляйте версию Codex автоматически
без проверки интеграции.

### 4. Соберите и запустите приложение

```sh
docker compose -f compose.host-proxy.yaml -f compose.password.yaml config --quiet
docker compose -f compose.host-proxy.yaml -f compose.password.yaml build --pull
docker compose -f compose.host-proxy.yaml -f compose.password.yaml up -d app
docker compose -f compose.host-proxy.yaml -f compose.password.yaml ps
```

Контейнер публикуется только на `127.0.0.1:18880`; порты 80/443 остаются у
Caddy. Данные получают отдельные постоянные тома. При неверном или
недоступном файле входа приложение должно отказаться запускаться.

Добавьте правило из
[deploy/Caddyfile.password-path.example](deploy/Caddyfile.password-path.example)
**внутрь существующего блока нужного сайта**. Шаблон направляет только
`/signs/*` в приложение и не добавляет Basic Auth. Сохраните предыдущую
конфигурацию, проверьте Caddy и примените её штатной перезагрузкой.
Не заменяйте целиком настройки действующего сайта и не запускайте второй Caddy.

Проверьте, что без cookie редактор показывает вход, API недоступен, а правильный
пароль открывает приложение. Сеанс действует 12 часов. При его истечении
редактор предлагает вход в новой вкладке, сохраняя несохранённое фото и ТЗ
в исходной.

### 5. Подключите подписку и данные

```sh
docker compose -f compose.host-proxy.yaml -f compose.password.yaml exec app codex login --device-auth
docker compose -f compose.host-proxy.yaml -f compose.password.yaml exec app python deploy/check-runtime.py --require-login
```

Откройте адрес, выданный Codex, и подтвердите одноразовый код в своём аккаунте.
На новом сервере вход выполняют заново; авторизация не входит в исходный архив
и не переносится вместе с историей. Проверка окружения подтверждает вход,
но для проверки доступности встроенной генерации на новом сервере нужен
один контролируемый запрос на реальном фото.

Для передачи подготовлен архив **`history-handoff-20261008.zip`** с 7 заданиями.
Это снимок на момент экспорта; более позднюю историю нужно выгрузить заново.
Восстановление требует корректных прав файла для UID 10001 и проверки
контрольных сумм. Используйте готовые процедуры резервного копирования и
восстановления из [DEPLOYMENT.md](DEPLOYMENT.md). Старый `history-vps.zip`
содержит только первые 6 заданий и не является полной текущей копией.

После импорта проверьте историю, исходники, результаты и сохранение данных
после перезапуска. Основной сайт должен продолжать отвечать как прежде.

## Разработка на другом компьютере

Исходники независимы от установленного навыка и Windows-путей. Для разработки
используются Python 3.12 и Node.js 22; зависимости закреплены в
[requirements.txt](requirements.txt). Полный порядок локального запуска и
проверок — в [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).

Локальный редактор можно запускать без веб-пароля на loopback. Для ИИ-режимов
нужны локальный Codex CLI и собственный вход через ChatGPT; обычное наложение
таблички/неона их не требует. Не переносите
серверный файл авторизации в среду разработки. Проверяйте работу интерфейса
и в корне локального сайта, и за префиксом `/signs/`.

Для обновления VPS создавайте новый выпуск, сохраняйте имена проекта Compose
и томов, используйте оба файла запуска. Резервное копирование, смена пароля
и откат описаны в [DEPLOYMENT.md](DEPLOYMENT.md). Не удаляйте тома при обновлении.

## Альтернативная прежняя схема с Basic Auth

Файлы `compose.yaml`, `deploy/Caddyfile`, `.env.example` и
`deploy/preflight.py` сохранены для прежней схемы: собственный Caddy в Docker
на отдельном новом сервере, логин и bcrypt-хеш пароля на уровне прокси.
Она отличается от текущего входа одним паролем.

Эта альтернатива **не предназначена для действующего `vm-app.ru`**:
её Caddy занял бы уже используемые порты 80/443. Для основного варианта выше
не требуется заполнять `EDITOR_USER`, `EDITOR_PASSWORD_HASH` и
`ACME_EMAIL` из старого `.env.example`, а `preflight.py` проверяет именно
прежнюю схему. Не смешивайте два способа запуска.
