# Разработка и диагностика

Прочитайте [HANDOFF.md](../HANDOFF.md) для требований пользователя,
[ARCHITECTURE.md](ARCHITECTURE.md) для устройства кода и
[DEPLOYMENT.md](../DEPLOYMENT.md) перед любыми действиями на VPS.

## Локальная среда

Python 3.12, Node.js 22 и зависимости из `requirements.txt`. Frontend состоит
из обычных HTML/CSS/JS: `npm install`, сборщик и dev-server не нужны. Codex
не нужен для unit-тестов и геометрического редактора; для реального imagegen
нужен CLI проверенной версии и собственный вход через ChatGPT.

Из корня распакованного проекта:

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/render_server.py --port 54735 --output ./local-history
```

В PowerShell активируйте `.\.venv\Scripts\Activate.ps1` вместо команды с `.`.
При необходимости запускайте `.venv`-интерпретатор непосредственно: изменение
общесистемной политики исполнения не требуется. Откройте
`http://127.0.0.1:54735/calibrator.html`. Для разработки без внешнего входа
не задавайте `EDITOR_AUTH_FILE` и `EDITOR_PUBLIC_ORIGIN`, не меняйте loopback
на общедоступный адрес.

Вход по паролю требует HTTPS: cookie имеет `Secure`, а сервер требует
HTTPS-origin. Проверяйте его unit-тестами либо через отдельный локальный
HTTPS-прокси. Не снимайте `Secure` и не отключайте Origin ради обычного HTTP.
Серверные секреты в локальную копию не переносите.

## Проверки

```sh
python -m unittest discover -s scripts -p 'test_*.py' -v
node scripts/test-geometry.cjs
node scripts/test-path-prefix.cjs
node scripts/test-ruler.cjs
node scripts/test-viewport.cjs
node scripts/test-generation-restore.cjs
node scripts/test-draft.cjs
node scripts/test-corel-launch.cjs
node scripts/test-products.cjs
node --check assets/calibrator.js
node --check assets/generation.js
node --check assets/history.js
node --check assets/preview.js
node --check assets/login.js
node --check assets/ruler.js
node --check assets/viewport.js
node --check assets/corel-export.js
node --check assets/draft.js
node --check assets/products.js
node --check assets/product-ui.js
```

Дополнительная проверка настоящего браузера:

```sh
node scripts/test-product-ui.cjs
```

Для неё нужен Playwright и установленный браузер Edge. Путь к Playwright можно
передать через `PLAYWRIGHT_MODULE`, канал браузера — через `TEST_BROWSER_CHANNEL`.
Тест создаёт отдельный локальный сервер с ответами-заглушками, проверяет
PNG-оригиналы, экспорт, переключение изделий и черновик. Он не запускает Codex
и не заменяет проверку серверного наложения; последняя входит в Python-тесты.

При добавлении продукта начинайте с [PRODUCTS.md](PRODUCTS.md). Проверяйте
JS-контракт и серверный контракт вместе. Стартовые настройки каталога не должны
заново применяться при чтении сохранённого проекта. Смена версии шаблона сама
по себе не меняет версию формата его параметров.

| Проверки | Что защищают |
| --- | --- |
| `test_render_server.py` | Валидацию фото/проекта, свет/маску, API, историю, Host/Origin, остановку. |
| `test_codex_render.py` | Отсутствие API-подмены/повторов, схему результата, ограничения файлов, подтверждённый перенос PNG. |
| `test_history_transfer.py` | Манифест, хеши, запрещённые пути, конфликты имён, отказ от перезаписи и откат импорта. |
| `test_editor_auth.py` | Хеширование, cookie и срок, вход/выход, ограничения попыток, защиту API и перенаправления. |
| `test-geometry.cjs` | Калибровку, прямое/обратное преобразование перспективы, строки, зазоры и SVG. |
| `test-path-prefix.cjs` | Работу frontend в `/signs/` и отсутствие запросов в корень основного сайта. |
| `test-ruler.cjs` | Настоящие `geometry.js`, `ruler.js` и `calibrator.js` в JS VM: добавление/удаление точек, CSS/фото-координаты, сегменты и сумму, Esc/отмену/очистку, JSON и восстановление. |
| `test-viewport.cjs` | Масштабирование у курсора, перемещение, вписывание/100%, исходные координаты, ограничения вида и сброс перемещения при потерянном отпускании кнопки. |
| `test-generation-restore.cjs` | Восстановление сохранённого результата без нового POST генерации и приоритет текущей работы. |
| `test-draft.cjs` | Локальное сохранение и восстановление фото, формы, вида и незавершённой разметки; приоритет действий пользователя и ошибки хранилища. |
| `test_corel_export.py` | Валидацию плоского ТЗ, безопасный XML, постоянный VBS в UTF-16 с BOM и состав ZIP без фото/секретов. |

Фактическое число тестов и результаты конкретного выпуска хранятся в
[TESTING.md](../TESTING.md). На Windows тест реальной файловой символьной
ссылки может быть пропущен из-за прав; на Linux его нужно выполнить.
Unit-тесты подменяют внешнего исполнителя и не расходуют лимит imagegen.
Проверки линейки не запускают генерацию. Наличие тестового файла не означает,
что новый выпуск уже проверен на Linux: фактический результат записывается
в `TESTING.md` после запуска.

После изменения интерфейса вручную проверьте загрузку фото, точечную разметку,
две строки и зазор, смену света, переход в историю, возврат через `restoreJob`,
предпросмотр и сохранение JSON/PNG. После изменения входа проверьте пароль,
истечение/невалидную cookie, 401 API, безопасный возврат в историю и отсутствие
потери уже введённых параметров при уведомлении об истёкшей сессии.
Для линейки проверьте левый клик, удаление правым в пределах 16 CSS-пикселей,
сумму после удаления средней точки, Esc с сохранением точек, очистку и возврат
из JSON. При ошибке размеров вывески правильная калибровка продолжает давать
замер; при ошибке калибровки или `same_plane:false` сантиметры скрываются.
Для нового вида проверьте точку эталона после zoom/pan, попадание правого клика
линейки, «Вписать», 100%, ограниченную высоту окна и обновление страницы с
локальным черновиком. У восстановления ИИ-результата не должно быть нового POST
генерации. Состояние в другом браузере не ожидается.
Для разметки эталона проверяйте видимость первой точки на портретном фото в
режиме «Вписать», постоянный размер меток, прогресс и продолжение после reload.
Повторите левый клик после потерянного `pointerup` средней кнопки и смены режима:
зависшее перемещение не должно перехватывать разметку. Экспорт SVG сохраняет
прежнюю геометрию; отдельный экранный слой не входит в экспорт.

Unit-тест ZIP не запускает CorelDRAW. После изменения VBS отдельно создайте
CDR в настоящем CorelDRAW 2024 на Windows, повторно откройте его и проверьте
кривые, габарит страницы, пропорциональные размеры строк, зазор и цвет. Пакет
без этого запуска не подтверждает работоспособность CDR. [Контракт и пример
проверки](CORELDRAW.md).

После изменения `codex_render.py`, промпта или композиции один контролируемый
запрос на реальном фото дополняет тесты. Он расходует лимит подписки и занимает
минуты. Сохраните ID, статусы, итоговый PNG и аудит; проверьте текст и
защищённые пиксели. Успешный login/status или `check-runtime` такого запроса
не заменяет. Повторять неудачный запрос автоматически нельзя.

## Где менять поведение

- Новое поле ТЗ: HTML → `calibrator.js` (сохранение/восстановление) →
  `references/project-format.md` → серверная валидация/промпт/аудит →
  сводка в `preview.js` и история, если поле важно там. Сохраните поддержку
  старых JSON без нового поля.
- Новый расчёт или правило размера: `geometry.js`, который работает и
  в браузере, и на сервере. Не дублируйте независимую геометрию на Python.
- Линейка: `ruler.js` рисует точки и подписи, `calibrator.js` обрабатывает
  события и хранит `project.ruler` (`image_points`, `same_plane`). Проверяйте
  независимость её расчёта от размещения вывески и совместимость старых JSON.
- Вид и черновик: `viewport.js` и `draft.js`; не записывайте экранные координаты
  в проект и не подменяйте локальным черновиком серверную историю.
- CDR: `corel-export.js` → `corel_export.py` → постоянный `Create-CDR.vbs`.
  Ввод передаётся только XML-данными. Сохраняйте отказ при отсутствии точного
  шрифта, пропорциональное вписывание и отсутствие генерации ИИ в этом пути.
- Материал/свет: `render_server.py`, согласованный UI и карточка цветов.
  Не обещайте физическое совпадение цвета без измерений материала.
- Изменение путей: относительный базовый URL в frontend, Caddy и тест
  префикса. Не меняйте глобальные маршруты основного сайта.
- Вход: `editor_auth.py`, обработчики в `render_server.py`, `login.*`,
  уведомления в генерации/истории, overlay Compose. Секреты остаются вне кода.
- Наблюдение за запросом: `generation.js` и состояние `Service`.
  Различайте повтор GET статуса и повторную отправку imagegen.

## Разбор неисправности

| Симптом | Что проверять |
| --- | --- |
| Редактор не открывается / 502 | Контейнер `app`, healthcheck, loopback-порт 18880, маршрут `/signs/`, логи приложения. Основной Caddy и другие сервисы без причины не перезапускать. |
| После входа снова страница пароля | Cookie Path, HTTPS, точный origin, системное время сервера, чтение файла `EDITOR_AUTH_FILE`, не менялся ли секрет сессий. |
| 429 при входе | Общий лимит неверных попыток за минуту; соблюдать `Retry-After`. |
| Codex не подключён | `codex login status` и `check-runtime.py --require-login` внутри правильного контейнера; при необходимости новый device login пользователем. |
| Генерация долго идёт | GET статуса текущего ID; таймаут Codex 900 секунд. Не нажимать повторно для создания нового ID. |
| Codex сообщил ошибку | `codex-result.json` и другие файлы именно этого задания. Полные stdout/stderr намеренно не сохраняются. Не выдавать предположение за подтверждённую причину. |
| PNG создан, но не принят | Явный путь результата, разрешённый каталог нативных файлов, время, формат, размер и `image-transfer.json`. Не выбирать случайную «последнюю картинку». |
| Изменены пропорции | Сервер отклоняет существенное изменение отношения сторон. Сверить исходный кадр и ТЗ; отключать защиту ради получения картинки нельзя. |
| Оттенок отличается от HEX | Профиль плёнки, исходная карточка, параметры света, сохранённый проект этой версии. У модели нет спектральных данных реального материала. |
| История пуста | Имя Compose-проекта и тома, `EDITOR_OUTPUT`, права 10001, валидность `project.json`. Новый пустой том не означает потерю прежнего. |

## Выпуск без затрагивания основного сайта

Точные команды размещения — в [DEPLOYMENT.md](../DEPLOYMENT.md). На действующем
выпуске каталог — `/opt/signage-editor/releases/20261009-vps6/vps-project`,
образ — `channel-letter-mockups:20261009-vps6`, `APP_VERSION=20261009-vps6`.
На VPS команды Compose используют **оба** файла:

```sh
docker compose -f compose.host-proxy.yaml -f compose.password.yaml config --quiet
docker compose -f compose.host-proxy.yaml -f compose.password.yaml ps
docker compose -f compose.host-proxy.yaml -f compose.password.yaml logs --tail=80 app
```

Перед обновлением — завершить генерацию, сохранить историю и прежний образ.
Выкладывать в отдельный выпуск, сохранить `signage-editor`, тома, порт,
домен и закрытый файл входа. Не использовать `down -v`, не запускать второй
Caddy и не заменять весь `/etc/caddy/Caddyfile` примером из проекта.
Проверить редактор и основной сайт; до удаления старого образа проверить откат.

В исходный архив включайте код и документацию. Исключайте `.env`, виртуальное
окружение, кеши, фото/историю, auth JSON, SSH-ключи, логи и авторизацию Codex.
Историю экспортируйте отдельным архивом с манифестом и передавайте закрыто.


Для локального помощника дополнительно запускайте `test_corel_helper.py`,
`test_corel_launch.py` и `node scripts/test-corel-launch.cjs`. Проверка реального
пути: создать билет кнопкой → разрешить запуск приложения в Windows-браузере →
дождаться «Готово» → проверить CDR, отчёт и открытое окно. Встроенный браузер
может не поддерживать сторонние URI. После изменения помощника повторите его
установку: уже скопированная версия сама не обновляется.
