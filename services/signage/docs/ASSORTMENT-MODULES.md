Расширение опубликовано на <https://vm-app.ru/signs/>: код
`5a5470cedcc3665a08ddfa28a19e83e4fd915809`, образ
`channel-letter-mockups:20261012-assortment-v1`, каталог
`/opt/signage-editor/releases/20261012-assortment-v1/vps-project`, контейнер healthy.

Доступны шесть семейств и 180 вариантов: 168 позиций в 15 исходных категориях

материалов или производственных мощностей. Для 107 сложных исходных позиций
нужен готовый PNG изделия с прозрачностью в нужном ракурсе; 3D-форма не строится.

История сохранила 14 проектов и все 174 файла; пароль, авторизация Codex и тома
не изменились. Production-проверка подтвердила восстановление прежней таблички,
идентичное состояние при legacy/redesign round-trip, историю 14/14 и все четыре
шага на 390/320 px без переполнения. При разработке, проверках и публикации
этого расширения запросов ИИ не было. Отчёт, доказательства и два разных вида
возврата — в [RELEASE-20261012-ASSORTMENT.md](RELEASE-20261012-ASSORTMENT.md).

Развитие от рабочего выпуска `20261012-interface-v2`. Общие фото, калибровка,
плоскость установки, проекты v1/v2, задания, история и переключение оформления
сохраняются. Каталог и описания полей вынесены в `assets/product-catalog.json`.
Это один источник данных для браузера, Node.js и Python.

## Что задаётся данными

- `families` — версии уже реализованных способов визуализации и их возможности;
- `modules` — виды изделий, привязанные к способу визуализации;
- `templates` — варианты ассортимента, начальные параметры и размеры.

Для нового варианта добавьте запись в `templates`. Для нового вида на базе
существующего способа добавьте запись в `modules` и его начальный шаблон.
Поля формы строятся из `field_schema`; ручное добавление HTML и новых ветвлений
в истории, калибровке или отправке заданий не требуется.

## Пример добавления модуля данными

Для нового баннера на уже установленном `flat_print` добавьте объект в
`modules` общего `assets/product-catalog.json`:

```json
{
  "type": "workshop_banner",
  "label": "Баннер по ТЗ",
  "module_version": 1,
  "renderer_family": "flat_print",
  "renderer_version": 1,
  "default_template_id": "workshop-banner-one",
  "defaults": {"opacity": 0.8},
  "fields": [
    "text", "font_family", "font_bold", "text_align", "line_gap_cm",
    "front_color", "brief", "material", "margin_mm", "opacity", "edge_note"
  ],
  "field_schema": [
    {
      "key": "edge_note",
      "label": "Обработка края по ТЗ",
      "kind": "string",
      "max_length": 160,
      "default": ""
    }
  ]
}
```

Затем добавьте его начальный вариант в `templates`:

```json
{
  "id": "workshop-banner-one",
  "type": "workshop_banner",
  "version": 1,
  "label": "Баннер с обработкой края",
  "category": "Печать",
  "description": "Плоский макет на подготовленной поверхности",
  "coverage_note": "Складки, каркас и швы не строятся; обработка края хранится как ТЗ.",
  "default_placement": {"width_cm": 150, "height_cm": 60, "rotation_deg": 0},
  "params": {"text": "ВАША НАДПИСЬ", "material": "Баннер", "edge_note": "Подгиб"}
}
```

Это пример будущего дополнения, не дополнительная позиция текущих 180 вариантов.
Оба объекта вставляются в существующие массивы; полный каталог и `families`
не заменяются. Сохраните `schema_version=1`, увеличьте `revision` каталога,
выберите уникальные `type`/`id` и свяжите `default_template_id` с шаблоном того же
`type`. Дополнительное поле не может заменять общий параметр или поле семейства.
Для `number` нужны `min`/`max`, для `select` — `options`, для `string` — `max_length`.

Поле `edge_note` появляется в форме, проверяется и сохраняется в `params`.
Оно не рисует подгиб или новую геометрию. Способ визуализации и допустимые
ИИ/экспорт определяет установленный обработчик `flat_print` версии 1.
Добавление такой записи не требует изменений общих калибровки, истории,
draft/auth или отправки заданий. Для одного нового варианта существующего
модуля достаточно записи в `templates` с прежним `type`.

После изменения JSON перезапустите локальный сервер и заново откройте
редактор. Для рабочего Docker-выпуска соберите образ с обновлённым JSON,
проверьте его и примените к тому же Compose-проекту с прежними томами.
Каталог и bootstrap читаются из одного файла, а не из отдельных
вручную поддерживаемых браузерных и серверных списков.

## Проверка будущего изменения без нарушения совместимости

Проверка перед выпуском в подготовленном окружении:

```sh
node scripts/check-product-catalog.cjs
node scripts/test-products.cjs
node scripts/test-catalog-ui.cjs
node scripts/test-path-prefix.cjs
python -B -m unittest discover -s scripts -p "test_*.py"
```

Сначала проверяются JSON, уникальные ID, связи с обработчиками и типы полей.
Затем — динамический ввод, исходный PNG, отдельные черновики, импорт v1/v2
и независимость сохранённого проекта от переименования/удаления шаблона,
новых defaults и схемы полей. Старые ID и контракт семейств версии 1 сохраняйте.
При расширении поставляемого каталога обновляйте ожидаемый список типов/числа
в каталожных тестах, сохраняя проверки неизменности и отказа неизвестным версиям.
Полный выпуск проверяйте в изолированном Linux-образе без production-томов.
В браузере вручную проверьте импорт старого проекта, новый модуль, переключение
оформления, сохранение/reload и мобильные шаги; такая проверка не требует ИИ.

Число карточек не зашито в разметку. Есть поиск и категории; каталожные
изображения с подписями не подставляются вместо оригинального макета.
Стартовые габариты — удобные настройки для начала работы, а не обмер,
производственная спецификация или подтверждение наличия материала.

## Способы визуализации

| Семейство | Что выполняется |
| --- | --- |
| `channel_letters` | Существующая ИИ-визуализация букв; прежний экспорт лицевых контуров CorelDRAW |
| `plaque` | Основание, поля и крепёж таблички; точный PNG в перспективе |
| `neon` | Точный PNG контура, подложка и условное свечение |
| `flat_print` | Плоская печать/наклейка из текста или своего PNG без добавленного основания |
| `lightbox` | Прямоугольная лицевая панель с точным PNG, условной глубиной и подсветкой |
| `cutout` | Готовый PNG изделия с прозрачным фоном в выбранном ракурсе |

Сложные стойки, сборные конструкции, изделия с несколькими сторонами,
обклейка криволинейной поверхности и подобные позиции в режиме `cutout`
получают готовое изображение от пользователя. Редактор размещает его на фото;
восстановление 3D-формы, развёртки, конструкции и скрытых сторон не заявляется.
Форма не разрешает заменить такой оригинал автоматически созданным текстом.
Точное начертание, логотип и QR берутся из предоставленного оригинала.

Настоящий новый способ визуализации требует реализации обработчика семейства
и его схемы, затем проверки проекции/маски и экспорта. Это локальная разработка
модуля; общий редактор, хранение, авторизация и история не дублируются.
Версии обработчиков и модуля меняются явно. Контракт семейства версии 1 нельзя
переписывать на месте. Новая геометрия или несовместимые правила требуют новой
версии и реализации её поддержки в коде: простая запись `renderer_version=2`
не подключит обработчик. Текущий выпуск исполняет установленные версии 1.

## Сохранённый проект

Изделие сохраняет собственные `params`, `placement`, PNG и версии обработчика.
`catalog_snapshot` содержит ID/версию, название, категорию, описание,
ограничения покрытия, исходный ID и правила обязательного PNG выбранного
варианта. `module_snapshot` сохраняет подпись, версию модуля, семейство/версию
обработчика и собственный `field_schema`. Значения `params`, размещение
и оригинальный PNG хранятся отдельно в самом изделии. Это самодостаточный
снимок выбранного изделия; весь изменяемый raw JSON каталога в проект не подмешивается.
Редактирование или удаление каталожного шаблона не пересчитывает старый проект.
При импорте используются сохранённые значения и совместимые значения по умолчанию
семейства версии 1; текущие настройки шаблона не подмешиваются.

Проекты v1 остаются объёмными буквами. Неизвестный обработчик или его версия
не выполняются автоматически. Исходный JSON и готовые артефакты должны оставаться
доступны из истории; пользователь получает понятное сообщение о невозможности
редактирования данным выпуском. Возможности ИИ и экспорта определяет установленный
обработчик, а не поля импортированного проекта.

В сцене по-прежнему одно изделие. Несколько изделий, отдельные плоскости и
автоматическое создание производственных файлов из PNG — самостоятельные
расширения, для которых этот выпуск не подменяет контракт.
