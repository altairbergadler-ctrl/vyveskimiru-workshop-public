# Архитектура приложения

## Модульная продукция (10 октября 2026)

Общее приложение и его отдельный жизненный цикл `/signs/` сохранены.
`assets/products.js` содержит реестр изделий, каталог шаблонов, миграцию
версии 1 в версию 2, проверки и доступные возможности. Этот модуль используется
браузером и Node.js. `geometry.js` проецирует активное изделие на общую плоскость,
сохраняя прежние вычисления для букв. Метаданные отчёта не дублируют PNG макета.

`product-ui.js` отвечает за выбор изделия, относящиеся к нему поля,
сохранение параметров при переключении, загрузку оригинального PNG и создание
текстового макета браузером. У загруженного оригинала сохраняется происхождение.
История и экспорт учитывают тип изделия; Corel остаётся возможностью букв.

`scripts/product_render.py` независимо проверяет контракт на сервере и
накладывает сохранённый PNG в рассчитанную перспективу. Задания используют
общую историю и защиту от повторной отправки. Три режима обработки:

- `codex`: прежняя ИИ-визуализация объёмных букв;
- `composite`: точный макет таблички/неона поверх световой основы без вызова ИИ;
- `codex_composite`: один вызов ИИ для очистки фона в разрешённой области,
  затем то же программное наложение сохранённого макета.

Подготовка фона не поручает ИИ рисовать текст нового изделия. Защита пикселей
вне разрешённой области проверяется после сборки. Для ночной таблички подсветка
не включается автоматически; состояние неона задаётся его параметрами.

Подробности расширения и границы выпуска: [PRODUCTS.md](PRODUCTS.md).

Описание реализации на 9 октября 2026 года. Это небольшой сервер на Python
со статическим интерфейсом без фреймворка, без базы данных и без сборки frontend.
Внешняя генерация вызывается через установленный Codex CLI.

## Клиентское состояние и путь приложения

Редактор хранит разметку в памяти страницы и автоматически сохраняет текущий
черновик в IndexedDB того же браузера. Черновик включает фото, проект и вид;
это локальное восстановление после перезагрузки, не синхронизация устройств.
Экспорт проекта — JSON версии 1 без фотографии, масштаба просмотра и учётных
данных. Последний готовый результат восстанавливается из серверной истории
без нового imagegen. База `signage-editor-drafts`, хранилище `drafts`, ключ —
базовый путь приложения; это один текущий черновик для браузера и адреса,
не менеджер нескольких проектов. Фото и проект записываются атомарно.
Малый журнал `localStorage` без фотографии сохраняет последние метаданные
для быстрого обновления страницы; он применяется только к той же версии фото.
Черновик также хранит активный инструмент, его незавершённые точки и исходные
значения полей формы, включая временно неполные или некорректные значения.
Это отдельный локальный снимок, а не изменение формата экспортируемого проекта.
События `signage:change`, `signage:viewchange`, `signage:resultchange` запускают
сохранение; интерфейс сообщает о недоступном или заполненном хранилище.

Явный `?restoreJob=` и новые действия пользователя имеют приоритет над старым
асинхронно прочитанным черновиком. `generation.draftState()` хранит ID готового
результата, выбранную вкладку и связь с текущим фото. Восстановление получает
изображение запросами GET, не заменяя текущие фото/параметры и не отправляя
генерацию. Уже выполняющийся запрос имеет приоритет над старым результатом.
Недоступный сервер или удалённый результат не уничтожает локальный проект.

`viewport.js` хранит масштаб и смещение отображения отдельно от метрической
калибровки. Колесо фиксирует точку под курсором, средняя кнопка перемещает вид;
масштаб 1 означает один пиксель исходника на CSS-пиксель, предел — 8. «Вписать»
использует размеры ограниченного окна. Преобразование события мыши возвращает
координаты исходного фото; за пределами видимого окна точки не ставятся.
Параметры вида могут храниться в локальном черновике, но не в JSON проекта.
Живые метки эталона рисуются отдельным слоем: диаметр 12 CSS-пикселей и подписи
14 пикселей не уменьшаются вместе с фотографией. Геометрический SVG этого вида
использует `includeReference:false`; экспорт по умолчанию сохраняет эталон и
прежнюю геометрию. Перемещение сбрасывается при `blur`, скрытии страницы, первом
левом клике и через `cancelPan()` при выборе режима разметки.

`generation.js` строит базовый URL через `new URL('.', location.href)`.
Маршруты API и ресурсов разрешаются относительно него: на VPS сохраняется
префикс `/signs/`. Отдельная страница истории использует тот же принцип.
Не переносите адреса на корень домена и не включайте `/signs/` в
`EDITOR_PUBLIC_ORIGIN`: origin равен `https://vm-app.ru`.

Номер отправленного задания сохраняется в `sessionStorage` под ключом
`signage-pending-job:<pathname приложения>`. После перезагрузки вкладки
проверяется существующий запрос. Это восстановление наблюдения, а не повторная
генерация. `?restoreJob=<id>` загружает с сервера проект, исходник и готовый
макет, если он есть; затем параметр удаляется из адреса.

В `window.SignageEditor` доступны снимок проекта, текущая область, загрузка
проекта с фото и экспорт PNG исходника. `window.SignageGeneration` возвращает
настройки света/зоны. Событие `signage:change` обновляет доступность генерации и
отметку об устаревшем результате.

## Пакет CorelDRAW

Пакет CorelDRAW — отдельная операция `POST /api/corel-package` с сессией,
Origin и токеном редактора. Он не запускает Codex и не создаёт запись истории:
сервер отдаёт ZIP в памяти, Windows-скрипт затем создаёт кривые средствами
CorelDRAW 2024. Формат, размерная модель, отсутствие подмены шрифта и проверка
настоящего CDR описаны в [CORELDRAW.md](CORELDRAW.md).

## Последовательность одной генерации

1. Браузер получает `/api/config`: статус входа Codex и токен текущего процесса
   сервера. По явному нажатию создаёт UUID и отправляет JSON с проектом и фото.
2. `Service.submit` под блокировкой проверяет ID и повтор запроса, состояние
   остановки, подключение Codex и отсутствие другой выполняющейся генерации.
3. `prepare` декодирует фото, применяет EXIF-ориентацию, сравнивает размеры с
   проектом, запускает `geometry.js` через Node, проверяет текст, материалы,
   рамку установки и выпуклый четырёхугольник зоны замены.
4. Один фоновый поток создаёт отдельную папку задания и сохраняет исходник,
   проект и статус. Рассчитывает световую основу без перемещения пикселей,
   маску, изображение для модели, схему положения и карточку цветов.
5. `codex_render.generate` вызывает Codex в папке задания. В промпте указаны
   точные строки, размеры, конструкция, свет и запрет менять геометрию. Рабочий
   процесс должен просмотреть три изображения и вызвать imagegen ровно один раз.
6. Codex возвращает JSON со статусом и точным абсолютным путём нативного PNG.
   Python проверяет путь, формат, время создания, размеры и переносит исходные
   байты в `generated.png`; перенос подтверждается SHA-256. Рабочий Codex не
   должен сам копировать файл через shell.
7. Сервер допускает равномерное приведение разрешения при сохранённом отношении
   сторон; отклонение отношения сторон больше 0,3% отклоняется. Затем берёт
   область генерации и вклеивает её в световую основу через маску с растушёвкой
   только внутрь контура. Ни один пиксель модели не должен попадать снаружи.
8. Программное сравнение проверяет нулевую разницу за маской. Сохраняются
   `render.png`, `audit.json`, завершённый статус; браузер показывает результат.

При ошибке статус становится `failed`. Ошибка сети или отсутствие подтверждённого
выхода не означает, что лимит подписки точно не расходовался. Автоматического
повтора, другого провайдера или подмены ИИ-результата кодовым рисунком нет.

## Геометрия, освещение и материалы

В режиме `frontoparallel` известный отрезок определяет приближённый единый
масштаб в одной плоскости. В `rectangle` четыре угла реального прямоугольника
и два его размера определяют гомографию. Координаты — пиксели ориентированного
исходника; физические величины — сантиметры плоскости. Измерения другой плоскости
с `same_plane:false` не получают выдуманного физического размера.

Интерактивная линейка использует `assets/ruler.js` и необязательное поле
`project.ruler`. Она хранит точки в исходных пикселях, преобразует их через
`geometry.measurePolyline` в координаты плоскости и суммирует сегменты.
Расчёт в интерфейсе не зависит от наличия или корректности размещения вывески.
Обработчики правого клика действуют только в режиме линейки; размер области
попадания и подписей привязан к экрану. Общий `overlaySvg` включает линейку в
экспорт, а живой слой использует `includeRuler:false`, чтобы не рисовать её
дважды. Изображения для генерации строятся отдельно и не содержат линейку.

Техническая схема задаёт общий габарит композиции. Многострочный текст использует
измеренные в браузере `preview_line_metrics` условного Arial при 100 px, а не
оценку длины по числу символов. Это не гарантирует реальный шрифт из ТЗ.

`relight` использует только поточечные операции RGB. Солнечный и облачный режимы
меняют тон/яркость, ночь затемняет исходную сцену. Они не создают физически
достоверные новые падающие тени по всему фасаду. Новые буквы и их местный свет
модель создаёт внутри разрешённой зоны.

Для `original` световая основа равна декодированному исходнику; в других режимах
она отличается цветом. Поэтому `changed_pixels_outside_edit_zone = 0` означает
равенство **световой основе**, а не неизменный цвет исходной фотографии ночью.
Внутри зоны маска не доказывает сохранность каждого шва или точность букв.

Профиль ORACAL описывает плёнку на акриле и прохождение внутреннего света через
лицевую часть. У бортов отдельный HEX и отсутствие собственного свечения.
`series`/`color_code` — строки из ТЗ; каталог и спектральные измерения отсутствуют.
Сервер создаёт нейтральную `color-reference.png` с исходными HEX без коррекции
света, но модель может менять вид материала в тенях. В аудите всегда указано
`color_accuracy: approximate_not_colorimetrically_verified`.

## Данные и состояния заданий

Каждому заданию соответствует `/data/jobs/<request_id>/`; СУБД нет.

| Файлы | Назначение |
| --- | --- |
| `project.json`, `job.json` | Параметры проекта; ID, время, свет, статус и безопасное сообщение. |
| `source.png`, `lighting-base.png` | Декодированный исходник и световая основа. |
| `edit-mask.png` | Маска разрешённой области в размере исходного кадра. |
| `render-input.png`, `placement-guide.png`, `color-reference.png`, `prompt.txt` | Вход модели, схема, цвета и техническое задание генератору. |
| `codex-output.schema.json`, `codex-result.json` | Схема конечного ответа и ответ рабочего Codex; не опубликованы через API. |
| `generated.png`, `image-transfer.json` | Нативный PNG и подтверждение его копирования без новой генерации. |
| `render.png`, `audit.json` | Финальная композиция и проверка геометрии/параметров. |
| `thumbnail.jpg` | Миниатюра до 480 × 360, создаётся по запросу и сохраняется атомарно. |

В памяти процесса есть словарь заданий и блокировка; длительной очереди нет.
Основные статусы: `running`, `complete`, `failed`; `interrupted` определяется
при чтении незавершённой папки после перезапуска. Наличие читаемого аудита и PNG
подтверждает сохранённый готовый результат. Статус `failed` сохраняется, если
так указано в `job.json`; остальные неполные задания считаются прерванными.
Их параметры можно открыть, но повторная отправка не происходит.

Одинаковый `request_id` и одинаковое тело запроса в одном процессе возвращают
текущий результат без нового вызова. С тем же ID и другим телом — ошибка.
После перезапуска существующая папка блокирует повторную отправку этого ID:
нужно читать историю. Это защита от двойного запроса, а не распределённая очередь.

Список истории собирается из папок на диске и сортируется по времени и ID по
убыванию. Ошибочные/неподдерживаемые записи пропускаются. Поиск применяется к
тексту вывески и ID без учёта регистра. История не изолируется по пользователям.

Экспорт истории включает только разрешённые файлы, манифест и SHA-256. Он не
включает авторизацию или произвольные файлы Codex. Импорт сначала проверяет
содержимое, запрещает выход путей, символические ссылки и конфликты имён,
отказывается перезаписывать существующие задания. Остановите активные генерации
перед снимком; экспорт отклоняет статус `running` или `queued`.

В vps3 `/downloads.html` и `/downloads/<имя>` дают доступ к трём заранее
подготовленным файлам из `/data/handoff` того же постоянного тома. Это отдельная
фиксированная разрешённая выдача по cookie, без `X-Editor-Token`, чтобы обычные
ссылки скачивания работали. Данные передаются порциями до 1 MiB, а не загружаются
целиком в память. Файлы размещает root с правами чтения для приложения;
авторизация, SSH-ключи и `.env` туда не попадают. Архивы не обновляются при новых
генерациях; имя исходного ZIP может остаться прежним при новом SHA-256.
В публичном режиме без встроенного входа эта выдача закрыта. Адрес пользователя:
<https://vm-app.ru/signs/downloads.html>.

## Интеграция Codex

Проверка подключения — `codex login status` с безопасным итоговым сообщением;
результат кешируется 20 секунд. `configured:true` подтверждает вход через
ChatGPT, но не остаток лимита и не успешность будущей генерации.

Текущая команда рабочего процесса:

```text
codex --no-daemon -a never -c model_provider="openai" exec --ephemeral
  --skip-git-repo-check -s workspace-write -C <папка-задания>
  --json --output-schema <схема> -o <результат-JSON> -
```

Промпт передаётся через stdin; shell для запуска не используется. Из окружения
дочернего процесса удаляются `OPENAI_API_KEY` и `CODEX_API_KEY`. Таймаут — 900
секунд. stdout/stderr Codex не собираются: там могут быть промпты, аргументы
инструментов и большие изображения. Конечный JSON ограничен 64 KiB и строго
проверяется. Нельзя полагаться на полный журнал tool calls как на имеющийся
диагностический артефакт.

Нативный результат принимается только по явно возвращённому пути внутри
`$CODEX_HOME/generated_images`, с проверкой канонического пути, обычного файла,
PNG, времени текущего вызова (допуск 5 секунд), одного кадра, лимита 100 MB и
50 млн пикселей. Поиска «последней картинки» нет. Поддерживается старый формат,
когда подтверждённый результат уже лежит в `generated.png` задания.

Версия CLI закреплена, поскольку схема инструментов и параметры могут меняться.
Обновляйте только после проверки полного реального запроса. Установленная
библиотека Python для OpenAI и внешний Images API не нужны.

## Доступ, сеть и завершение

Действующий вариант использует собственную страницу входа без имени пользователя.
Пароль проверяется `editor_auth.py`, Caddy обеспечивает HTTPS. Внешний Basic Auth
из первоначального выпуска заменён этим механизмом только для редактора.
Вызов с `EDITOR_AUTH_FILE` включает вход; некорректный или непрочитанный файл
останавливает запуск, а не отключает защиту. Отсутствие этой настройки сохраняет
старый режим, в котором аутентификация должна быть обеспечена прокси.

Закрытый JSON содержит PBKDF2-HMAC-SHA256 хеш, случайную соль, 600 000 итераций,
отдельный случайный секрет сессий, путь cookie и срок действия. Его нет внутри
образа, исходников или истории. `compose.password.yaml` монтирует путь
`EDITOR_AUTH_HOST_FILE` как `/run/secrets/editor_auth.json` только для чтения.
Создание конфигурации выполняется через скрытый интерактивный ввод:

```sh
python scripts/editor_auth.py create --output /АБСОЛЮТНЫЙ/НОВЫЙ/ФАЙЛ.json --cookie-path /signs/
```

Команда создаёт новый файл с правами `0600` и не перезаписывает существующий.
На сервере обеспечьте чтение UID 10001 согласно инструкции эксплуатации.
Не передавайте пароль в аргументах процесса. Для смены пароля создайте новый
файл, обновите его путь и перезапустите редактор. Смена хеша пароля, секрета или
пути cookie делает прежние сессии недействительными.

Cookie `__Secure-signage_session` имеет `Secure`, `HttpOnly`, `SameSite=Strict`,
`Path=/signs/`; срок по умолчанию — 12 часов. Значение включает срок истечения,
случайный идентификатор и HMAC-подпись. Отдельной таблицы сессий нет. Logout
очищает cookie браузера, но не создаёт серверный список отзыва ранее выданных
подписанных значений. Пароли и cookie не записываются в browser storage или
артефакты генерации.

До входа открыты лишь `login.html/js/css` и минимальный `/healthz`.
Защищённые страницы перенаправляют на вход кодом 303, API возвращает 401 с
`auth_required:true`. Безопасный `next` допускает только редактор, историю, страницу передачи и
валидный `restoreJob`; внешних redirect нет. `POST /auth/login` требует точного
Origin и JSON до 4096 байт. После пяти неверных попыток за минуту включается
ограничение для всего экземпляра с `429` и `Retry-After`; это общий счётчик в
памяти, не постоянная блокировка аккаунта и не отдельный лимит на IP.

Токен `X-Editor-Token` случайный для процесса и возвращается `/api/config`.
Это защита от CSRF, а не пароль пользователя. При включённом входе `/api/config`
сначала требует действительную cookie. Остальные API требуют и cookie, и токен.
Login токена редактора не требует; logout требует cookie, правильного Origin
и токена. Без встроенной авторизации или защиты прокси публикация `/api/config`
раскрыла бы токен любому посетителю. Нельзя открывать backend прямо в интернет.

Проверяются единственный точный Host и Origin из `EDITOR_PUBLIC_ORIGIN`.
Публичный POST требует явный Origin; `X-Forwarded-*` не определяют доверенный
адрес. Caddy передаёт исходный Host и снимает префикс пути. Значение origin
должно быть каноническим HTTPS-адресом без пути, query, логина и `:443`.
Запуск на не-loopback без настроенного origin запрещён, но наличие origin
само по себе не создаёт аутентификацию.

Для HTTP установлены `no-store`, `nosniff`, CSP с ресурсами своего origin,
запретом iframe и объектов. Файловая выдача использует список разрешённых
имён; служебный `auth.json` не выдаётся. Docker работает как 10001:10001 с
снятыми capabilities, `no-new-privileges`, ограничениями RAM/CPU/PID. Эти меры
не делают экземпляр сервисом для недоверенных клиентов: у него общая подписка,
общая история и процесс исполнения Codex.

При SIGTERM/SIGINT сервер отклоняет новые генерации, прекращает HTTP-обслуживание
и ждёт текущие потоки до 930 секунд. Compose даёт 16 минут на остановку.
Принудительное завершение может оставить прерванное задание. `/healthz`
проверяет состояние HTTP-сервера, не доступность OpenAI и не лимит подписки.

Основные переменные: `EDITOR_HOST`, `EDITOR_PORT`, `EDITOR_OUTPUT`,
`EDITOR_PUBLIC_ORIGIN`, `EDITOR_AUTH_FILE`, `CODEX_HOME`; CLI-флаги сервера могут
переопределять первые пять. `EDITOR_AUTH_HOST_FILE` используется Compose для
пути секрета на хосте. Рабочее размещение и безопасные команды изменения Caddy — в
[DEPLOYMENT.md](../DEPLOYMENT.md).

## Открытие CorelDRAW по кнопке (vps8)

`corel_launch.py` хранит временные билеты в памяти. `corel-export.js` создаёт
билет и запускает `signage-corel://open/<id>`, сохраняя редактируемую страницу.
`corel_helper_install.py` устанавливает частную среду Python и обработчик HKCU.
`corel_helper.py` получает параметры только с фиксированного HTTPS-адреса,
проверяет их через `corel_export.py`, затем запускает локальный VBS с `/quiet /open`.
Никакие сценарии с сервера не выполняются. [Контракт API](API.md) и
[порядок установки](CORELDRAW.md).
