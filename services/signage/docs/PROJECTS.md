# Проекты и история вариантов

Проект имеет постоянный ID, название и текущий серверный черновик. Генерации
принадлежат проекту, но их фото, настройки и результаты остаются неизменными.
«Продолжить редактирование» открывает текущие правки; «Редактировать этот вариант»
восстанавливает настройки конкретной генерации. Открытие не отправляет генерацию.

Черновик сохраняется на сервере после изменения фото, параметров, калибровки,
исходной графики или незавершённых действий разметки. Для сохранения не требуется
готовая калибровка или ИИ. Название редактируется над рабочей областью. Масштаб
просмотра сам по себе не меняет серверную версию проекта.

Локальный IndexedDB и журнал сохраняют резервную копию при потере связи. Статус
«Проект сохранён на сервере» подтверждает серверный commit. До этого правки могут
быть доступны только на текущем устройстве. При конфликте версий автоматической
перезаписи нет: можно открыть серверную версию или сохранить правки копией.

Старые генерации отображаются отдельными виртуальными проектами `legacy-<jobid>`.
Связь между ними не угадывается по фото или тексту. В истории можно явно выбрать
проекты и объединить: варианты всех выбранных проектов войдут в итоговый проект,
название и текущий черновик выбранной цели сохранятся. Другие черновики остаются
в хранилище; файлы вариантов не удаляются. Открытые до объединения редакторы
получат конфликт при попытке сохранить устаревшую версию.

## Хранилище и API

`/data/jobs` сохраняет прежний формат. Новое хранилище —
`/data/projects/projects.sqlite3` в том же постоянном томе. Транзакция SQLite
сохраняет черновик, исходное фото и номер версии атомарно. Фото дедуплицируются
по SHA-256. Название — до 160 символов; запрос сохранения — до 30 МиБ; прежний
предел исходного фото — 20 мегапикселей. Чтение старой истории не запускает миграцию.

| Маршрут | Назначение |
| --- | --- |
| `GET /api/projects?limit=24&offset=0&q=` | Карточки проектов, поиск и количество вариантов. |
| `GET /api/projects/<id>` | Актуальный черновик, исходное фото, состояние результата и revision. |
| `GET /api/projects/<id>/jobs` | Варианты проекта с прежними артефактами. |
| `POST /api/projects/<id>` | `{base_revision,name,snapshot,generation}`; новая версия или HTTP 409. |
| `POST /api/projects/merge` | `{project_ids,target_id}`; явное объединение. |
| `POST /api/jobs` | Прежний запрос плюс необязательные `project_id` и `source_job_id`. |

Все новые API используют действующую сессию и токен редактора; POST дополнительно
сохраняет проверку Origin/Host. Старые `/api/history` и `?restoreJob=` совместимы.
`?restoreProject=<id>` открывает текущий черновик, `?newProject=1` создаёт новый.

## Резервная копия и откат

Прежний `history_transfer.py` экспортирует только задания. Теперь резервная копия
должна включать и `projects`: остановите приложение и сохраните всю папку вместе
с возможными WAL/SHM либо используйте `sqlite3.Connection.backup()` для согласованной
копии базы. Простое копирование одного sqlite3-файла при работающем приложении
не является согласованной резервной копией.

Откат образа сохраняет тома и новые серверные черновики. Прежний выпуск продолжит
читать генерации, но его интерфейс не показывает серверные правки и группы.
