# HTTP API редактора

## Дополнения модулей изделий (10 октября 2026)

`POST /api/jobs` по-прежнему принимает `{request_id, project, photo}`.
Проект версии 1 сохраняет прежнее поведение. В версии 2 параметры и размещение
берутся из единственного активного элемента `products`, указанного полем
`active_product_id`; возможные старые поля `sign`/`placement` не переопределяют
каноническое изделие. Неподдерживаемый тип/версия модуля или несколько изделий
дают ошибку до создания задания.

`project.generation.engine`: `codex` для букв, `composite` для табличек и неона,
`codex_composite` для подготовки фона с ИИ и последующего точного наложения.
Если engine отсутствует, выбирается стандартный режим данного изделия.
`composite` не требует подключения Codex и не вызывает внешнюю генерацию.
Статусы, токен, проверка Origin, история и защита от повторов общие.

`GET /api/config` дополнительно возвращает `composite_configured` и
`product_types`. В сохранённых заданиях доступны метаданные продукта и engine.
В разрешённые артефакты добавлен `artwork.png` — точный исходный PNG изделия.
Артефакт требует те же cookie и `X-Editor-Token`, что и остальные файлы задания.

`product.artwork` содержит `name`, `mime_type: "image/png"`, `data_url`,
`width_px`, `height_px`, `source: "text" | "uploaded"`. Максимум 2 МиБ PNG,
4096 пикселей по стороне и 16 мегапикселей; анимация и пустой прозрачный файл
не принимаются. Для неона требуется прозрачность вокруг контура. Проект v2
ограничен 4 МиБ UTF-8; общий лимит HTTP-тела остаётся 30 МиБ. Загруженный SVG
в качестве исходного макета этим интерфейсом не принимается.

Текущий префикс снаружи: `https://vm-app.ru/signs`. В таблицах пути приведены
относительно приложения: например, `/api/config` снаружи означает
`https://vm-app.ru/signs/api/config`. Caddy снимает `/signs` перед backend.
API предназначено для интерфейса этого частного экземпляра, не для внешнего
публичного сервиса.

## Доступ и общий формат

Сначала пройдите вход редактора на `/login.html`: требуется только пароль,
без имени пользователя. После успешного `POST /auth/login` браузер получает
защищённую cookie. Примеры не содержат действующего пароля. Описанный режим
включается через `EDITOR_AUTH_FILE`; действующий VPS его использует.

Получите `GET /api/config` и передавайте возвращённый `token` в заголовке
`X-Editor-Token` для всех остальных `/api/*` и для выхода `/auth/logout`.
Cookie передаётся вместе с ним. Токен меняется после перезапуска
процесса; обновите конфигурацию. Это не API-ключ OpenAI и не пароль пользователя.
Изображения также получаются авторизованным fetch с этим заголовком, после чего
браузер показывает blob URL. Прямая вставка адреса защищённого PNG в `<img>`
не передаст этот токен.

Публичный POST обязан содержать `Origin: https://vm-app.ru` и корректный Host.
Для запросов с JSON нужны также `Content-Type: application/json` и
`Content-Length`. Браузер устанавливает Origin/Host самостоятельно.
Backend не разрешает произвольные CORS-источники.

JSON кодируется UTF-8. Ошибки имеют форму `{"error":"текст"}`. GET и POST
отвечают `Cache-Control: no-store`. Время `created` — Unix timestamp в секундах.
Не храните токен или пароль в экспортированном проекте.

## Маршруты

| Метод и путь | Ответ и назначение |
| --- | --- |
| `GET /` или `/calibrator.html` | HTML редактора. |
| `GET /history.html` | HTML истории. |
| `GET /downloads.html` | Страница передачи исходников и снимка истории; требуется cookie входа. |
| `GET /downloads/<имя>` | Потоковая выдача одного из трёх разрешённых файлов; требуется cookie, `X-Editor-Token` не нужен. |
| `GET /login.html`, `/login.js`, `/login.css` | Публичная страница входа и её ресурсы при включённой авторизации. |
| `POST /auth/login` | Проверка пароля, `200 {"ok":true}` и `Set-Cookie`. Не требует сессии или токена редактора, требует корректный Origin. |
| `POST /auth/logout` | `200 {"ok":true}` и очистка cookie. Требует сессию, Origin и `X-Editor-Token`; тело не используется. |
| `GET /healthz` | `200 {"status":"ok"}`; при завершении `503 {"status":"stopping"}`. Не подтверждает работоспособность генератора. |
| `GET /api/config` | `200` со статусом входа Codex, токеном, провайдером и названием модели. Не требует `X-Editor-Token`, но требует действительную сессию. |
| `POST /api/jobs` | `202` с состоянием принятого задания. Не дожидается генерации. |
| `GET /api/jobs/<id>` | `200` с текущим или сохранённым состоянием задания. |
| `GET /api/history` | `200` с записями, общим числом и параметрами страницы. |
| `GET /api/jobs/<id>/<файл>` | Сохранённый разрешённый артефакт. |

Разрешённые файлы: `render.png`, `source.png`, `lighting-base.png`,
`thumbnail.jpg`, `project.json`, `audit.json`, `artwork.png`. `generated.png`, маска, промпт,
ответ Codex и его авторизация через этот маршрут не публикуются. Нет маршрутов
удаления задания, отмены генерации, редактирования истории или автоматического
повтора. Неподдерживаемые HTTP-методы не реализованы.

Для `/downloads/<имя>` разрешены только `signage-editor-handoff.zip`,
`history-handoff-20261008.zip` и `SHA256SUMS-handoff.txt` из `/data/handoff`.
Это готовые статические файлы, не запрос экспорта и не новая генерация.
Без сессии скачивание перенаправляет кодом 303 на вход, после него открывается
`downloads.html`; выберите файл там. В публичном режиме без встроенной
cookie-авторизации этот маршрут возвращает 403. Неизвестное имя, отсутствующий
файл, выход за каталог или символическая ссылка дают 404. Файлы выдаются с
`Content-Length`, `Content-Disposition: attachment`, `no-store` и `nosniff`.
Нет просмотра каталога, загрузки файлов или токена в query string.
Страница: <https://vm-app.ru/signs/downloads.html>.

## Пакет лицевой части для CorelDRAW

`POST /api/corel-package` требует cookie, Origin и `X-Editor-Token`, как
остальные запросы редактора. Тело — JSON с полями `text`, `width_cm`,
`height_cm`, `line_gap_cm`, `text_align`, `font_family`, `font_bold` и
`front_color`. Ответ — `application/zip`, имя `letters-coreldraw-2024.zip`.
Редактор передаёт `front_color: "#000000"`: векторные буквы в CDR чёрные,
цвет макета на фото задаётся отдельно. API для совместимости продолжает
принимать любой цвет `#RRGGBB` и сохраняет переданное значение в XML.
В ZIP находятся XML-параметры, постоянный Windows-скрипт и инструкция.
Настоящий CDR создаётся установленным на рабочем ПК CorelDRAW 2024.
Фото не передаётся, задание генерации и запись истории не создаются.
Ограничения и пример запроса: [CORELDRAW.md](CORELDRAW.md).

## Вход и выход

`POST /auth/login` принимает `{"password":"<введённый пароль>"}`. У запроса
должен быть один `Content-Length`, JSON размером 1–4096 байт, без
`Transfer-Encoding`. Пароль — непустая строка не больше 1024 байт UTF-8.
`X-Editor-Token` и прежняя сессия для входа не нужны. Ошибка пароля даёт HTTP
401; после пяти неверных попыток за 60 секунд ограничение действует на весь
экземпляр приложения и возвращает HTTP 429 с `Retry-After` в секундах.

Успешный ответ `{"ok":true}` устанавливает cookie `__Secure-signage_session`:
`Secure; HttpOnly; SameSite=Strict; Path=/signs/; Max-Age=43200` в действующем
размещении. В JavaScript не нужно и нельзя читать HttpOnly cookie; браузер
передаёт её сам при обращении к приложению по HTTPS.

У неавторизованных API ответ выглядит так:

```json
{"error":"Войдите в редактор с паролем.","auth_required":true}
```

HTML-страницы вместо этого возвращают 303 на `login.html?next=...`. Значение
`next` допускает только `calibrator.html`, `history.html`, `downloads.html` и редактор с одним
валидным `restoreJob`; произвольный внешний URL не поддерживается. При
истечении сессии открытая страница показывает уведомление о повторном входе,
не отправляя генерацию заново и не скрывая неопределённый исход запроса.

`POST /auth/logout` требует cookie, точный Origin и токен редактора, отвечает
`{"ok":true}` и cookie с `Max-Age=0`. Тело запроса не используется. Выход очищает
cookie этого браузера; серверного списка отозванных токенов нет. Общее
аннулирование сессий выполняется сменой конфигурации пароля и перезапуском.

## Конфигурация

Пример `GET /api/config`:

```json
{
  "configured": true,
  "connection_message": "Подключено к ChatGPT через установленный Codex. Действуют лимиты подписки.",
  "provider": "codex",
  "token": "<случайный токен процесса>",
  "model": "Codex imagegen"
}
```

`configured` означает успешную проверку `codex login status`, которая кешируется
20 секунд. Она не подтверждает оставшуюся квоту, доступность imagegen или
возможность выполнить конкретное редактирование.

## Создание задания

```json
{
  "request_id": "example-job-00000001",
  "project": {
    "version": 1,
    "image": {"name": "facade.png", "width_px": 1600, "height_px": 1000},
    "calibration": {
      "mode": "frontoparallel",
      "plane": "плоскость вывески",
      "frontoparallel_assumed": true,
      "image_points": [[200,700],[680,700]],
      "length_cm": 120
    },
    "placement": {
      "center_px": [800,350], "width_cm": 220, "height_cm": 45,
      "rotation_deg": 0
    },
    "sign": {
      "text": "ЦВЕТЫ\nИ БУКЕТЫ", "line_gap_cm": 5, "text_align": "center",
      "font_family": "Arial", "depth_cm": 5,
      "front_color": "#FFF3DC", "side_color": "#292F30",
      "face_material": {
        "type": "film_on_acrylic", "brand": "ORACAL", "series": "",
        "color_code": "", "finish": "unspecified", "acrylic": "unspecified",
        "led_temperature_k": null, "day_lighting": "off"
      },
      "brief": ""
    },
    "target_polygon_px": [[250,180],[1350,180],[1350,550],[250,550]],
    "generation": {
      "lighting": "original",
      "edit_polygon_px": [[250,180],[1350,180],[1350,550],[250,550]],
      "geometry_lock": true,
      "background_cleanup": "inside_edit_zone_only",
      "night_illumination_required": true
    }
  },
  "photo": "data:image/png;base64,<байты изображения>"
}
```

Координаты выше учебные. Передавайте реальные данные фотографии. Полный формат
и значения перечислений описаны в [project-format.md](../references/project-format.md).
Клиентские расчёты не считаются доверенными: сервер пересчитывает геометрию.
Значение `false` в `geometry_lock` не отключает защиту геометрии.
Для объёмных букв `night_illumination_required: false` не отключает обязательную
подсветку ночного режима. У неона состояние свечения задаётся параметрами изделия.

Условия приёма:

- ID: 16–80 символов из `a-z`, `A-Z`, `0-9`, `_`, `-`; интерфейс использует UUID.
- Полное тело запроса: от 1 байта до 30 MiB, включая base64.
- Проект v1: до 100 000 символов сериализованного JSON; v2: до 4 MiB.
- Фото: PNG/JPEG/WebP в base64 data URL, не более 20 млн пикселей; после
  EXIF-ориентации размеры обязаны совпасть с `project.image`.
- Текст букв: непустой, до 300 символов; `brief` и `font_family` — до 4000 каждый.
  Для таблички и неона текстовый режим допускает до 3000 символов; оригинал PNG
  может использоваться без текста.
- Цвета: `#RRGGBB`. Материалы проверяются отдельно; LED либо `null`, либо
  конечное число от 1000 до 20000 K.
- Зона замены: четыре конечные точки в кадре, выпуклый контур в порядке обхода,
  от 0,01% до 65% площади кадра; должна содержать весь габарит вывески.
- Для `codex` и `codex_composite` подключён Codex. Для всех движков сервер
  не завершается, другое задание не выполняется.

При совпадении ID и тела в текущем процессе сервер возвращает то же задание.
При том же ID с другим телом или уже существующей папке после перезапуска —
ошибка. HTTP `202` не означает, что изображение уже создано. При обрыве POST
проверяйте `GET /api/jobs/<тот же id>`, не создавайте автоматически новый ID.

## Статус задания

```json
{
  "id": "example-job-00000001",
  "status": "running",
  "message": "Генерация через подписку ChatGPT / Codex…",
  "created": 1791473798.89,
  "lighting": "original"
}
```

Варианты `status`:

| Статус | Значение |
| --- | --- |
| `running` | Выполняется один рабочий запрос. Интерфейс опрашивает раз в 2,5 секунды. |
| `complete` | Сохранены итоговый PNG и аудит; поле `audit` есть в ответе задания. |
| `failed` | Известная ошибка; `message` содержит безопасное описание. Изображение может быть не подтверждено. |
| `interrupted` | После перезапуска найдены параметры без подтверждённого результата; автоматического продолжения нет. |

У завершённого задания `audit` включает размеры кадра, число защищённых и
изменённых пикселей, хеши защищённых данных, `source_spatial_transform`, свет,
материалы, запрошенные цвета, допущения, пересчитанную геометрию и при наличии
квитанцию переноса нативного PNG. Для проверки кадра ключевое поле:
`changed_pixels_outside_edit_zone == 0` относительно световой основы.

## История

`GET /api/history?limit=24&offset=0&q=цветы`

- `limit`: по умолчанию 24, ограничивается диапазоном 1–100.
- `offset`: по умолчанию 0, отрицательное значение приводится к 0.
- `q`: поиск по тексту вывески и ID без учёта регистра, первые 300 символов.
- Не-целочисленные параметры страницы дают HTTP 400.

```json
{
  "items": [{
    "id": "example-job-00000001", "created": 1791473798.89,
    "status": "complete", "lighting": "original", "text": "ЦВЕТЫ\nИ БУКЕТЫ",
    "front_color": "#FFF3DC", "side_color": "#292F30",
    "face_material": {"type": "custom"}
  }],
  "total": 1,
  "limit": 24,
  "offset": 0
}
```

Порядок — сначала новые, затем ID по убыванию при равном времени. `total` —
число совпадений фильтра. Для проекта из примера создания здесь был бы сохранён
его полный `face_material`; `custom` показывает допустимый старый проект без
профиля плёнки. API не возвращает полный проект для каждой карточки: получите
отдельно `project.json`.

## Ошибки и восстановление

| HTTP / ситуация | Действие клиента или администратора |
| --- | --- |
| `400` | Проверить сообщение: валидация проекта, занятость генератора, повтор ID, отсутствие входа или завершение сервера. Не все эти случаи являются ошибками формата JSON. |
| `401` | Для API с `auth_required:true` — пройти вход редактора. На `/auth/login` — неверный пароль. |
| `403` backend | Проверить Host/Origin, обновить страницу/токен после перезапуска. |
| `404` | Задание/файл не сохранены либо недоступны; проверить историю. Не считать это разрешением автоматического повторного расхода лимита. |
| `413` | Уменьшить фото и заново разметить точки; ограничения прокси и backend могут отличаться сообщением. |
| `415` | Передать `application/json`. |
| `429` входа | Выждать число секунд из `Retry-After`, затем снова ввести пароль. Не повторять запрос в цикле. |
| `500` | Серверная ошибка, автоматического повтора нет. |
| `502/503` прокси | Проверить контейнер, логи и `/healthz`; это не подтверждение ошибки конкретного imagegen. |
| `status=failed`, таймаут Codex | После 15 минут результат неизвестен; сохранить ID, проверить артефакты и историю, не запускать запрос повторно автоматически. |

Подробности конкретного провайдера не выдаются из сырого stdout/stderr в
интерфейс. Для диагностики администратор проверяет безопасный статус, папку
задания, `codex-result.json`, `image-transfer.json`, `audit.json` и окружение
через `check-runtime.py`. Не публикуйте авторизацию или всё содержимое тома Codex.

## Передача задания локальному CorelDRAW (vps8)

- `POST /api/corel-launch`: сессия, Origin и X-Editor-Token; JSON как у
  corel-package. Ответ 201: id (64 hex), launch_url, status_token, expires_in.
- `GET /api/corel-launch/{id}`: сессия, X-Editor-Token и X-Corel-Status-Token.
  Статусы pending, claimed, complete, failed, expired.
- Нативный `POST /api/corel-launch/{id}/claim`, JSON `{}`: строго без Origin;
  одноразовый id заменяет cookie. Ответ specification и completion_token.
  Повторное получение — 409.
- Нативный `POST /api/corel-launch/{id}/complete`: completion_token,
  status complete/failed, необязательные message (до 300 символов), filename
  (CDR basename до 160). Идентичный повтор отчёта — 200, изменённый — 409.

Исключение из cookie применяется только к точным нативным маршрутам; Host
проверяется. Билеты живут в памяти (pending 300 с, claimed 900 с, завершённые
ещё 900 с), максимум 128 активных. Перезапуск их сбрасывает. История ИИ не
меняется. Сервер отправляет только параметры; помощник запускает свой локальный
скрипт, отклоняет перенаправления, не получает пароль или авторизацию Codex.
На VPS все маршруты имеют префикс `/signs`.
