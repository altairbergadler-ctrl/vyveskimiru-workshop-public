# Инструмент печати в Мастерской

Основной адрес: https://vm-app.ru/tools/stamp/. Пункт «Оттиск» находится в разделе «Инструменты» меню владельца основного приложения. Отдельного логина/пароля инструмента нет; доступ наследуется от действительной finance_session Мастерской. Ролевые границы мастеров не расширяются.

## Размещение

- Отдельный контейнер workshop-stamp; конфигурация compose.workshop.yaml.
- Источник выпуска с печатями и подписями: /opt/finance-pwa/tools/stamp-service/releases/20261012-vps6.
- Текущий код: /opt/finance-pwa/tools/stamp-service/current (ссылка на выпуск).
- Постоянные данные: /opt/finance-pwa/tools/stamp-service/shared/data, UID/GID 10001:10001.
- Приватная конфигурация: shared/deployment.env; .env выпуска указывает на неё. Она не содержит отдельного пароля печати.
- Внутренняя сеть: finance-pwa_default; проверка владельца: http://finance-pwa:3000/api/session.
- Loopback-порт: 127.0.0.1:8187, HTTPS-маршрут в действующем Caddy /tools/stamp/.

Из каталога текущего выпуска: docker compose --env-file .env -f compose.workshop.yaml up -d --build. Требуются AUTH_MODE=workshop, WORKSHOP_AUTH_URL и STAMP_IMAGE=workshop-stamp:20261012-vps6. Caddy снимает /tools/stamp, а command Uvicorn восстанавливает префикс ASGI через --root-path /tools/stamp; это необходимо и для StaticFiles в установленной Starlette.

## Проверки

Без finance_session API отвечает 401. Недоступность основной сессии/сервера даёт 503 и не открывает данные. Проверяется именно authenticated=true в ответе API, а не только HTTP 200. Подмена/добавление cookie и перенаправления проверки запрещены. POST требуют CSRF и проверку Origin/Referer. Cookie владельца не сохраняется в файлах или журнале инструмента.

Статическая оболочка доступна без сессии, но не отдаёт документы, результаты или оттиски. При отсутствии входа интерфейс открывает основное приложение. Отдельная кнопка выхода скрыта. Постоянная кнопка «В Мастерскую» в верхней панели ведёт на https://vm-app.ru/; панель остаётся видимой при прокрутке и на узком экране.

## Восстановление

История, оттиски, подписи signatures/signatures.json, результаты, исходные сканы stamp-sources и csrf-secret находятся в shared/data и не меняются при переключении current. Перед обновлением сохранить приватную копию shared и текущей конфигурации Caddy. Для копии данных остановить только workshop-stamp, скопировать shared, затем запустить его. При остановке дать до 90 секунд на завершение текущей ограниченной операции.

При откате переключить current на прежний проверенный исходник и STAMP_IMAGE на соответствующий сохранённый образ, затем docker compose up -d --no-build. Не удалять shared/data. Удаление маршрута Caddy либо остановка контейнера отключает доступ, сохраняя файлы.

Выпуск основного приложения выполняется исключительно штатным deploy/install-workshop.sh с полной свежей копией. Он сохраняет текущий Caddy, включая маршрут печати. Итоговые доказательства и фактические версии — docs/VPS-VERIFICATION.md.
