# Подписи и совместная сборка: серверный контракт

Все пути находятся под APP_BASE_PATH. Источники, PNG и результаты доступны только через действующую сессию владельца Мастерской в AUTH_MODE=workshop либо прежний локальный сеанс в AUTH_MODE=password. Изменяющие запросы требуют X-CSRF-Token. Подпись здесь — изображение, помещаемое в документ; криптографическая электронная подпись не создаётся. PDF с уже существующей электронной подписью или полем для неё отклоняется, чтобы не изменять подписанный документ.

## Библиотека подписей

| Запрос | Результат |
| --- | --- |
| GET /api/signatures | `{items:[signature],active_id}`; новые элементы первыми |
| POST /api/signatures | multipart с file PNG и полями name, signer, width_mm; создаёт и выбирает новый элемент, возвращает библиотеку |
| POST /api/signatures/{id}/activate | Выбирает существующую подпись для следующих загрузок; возвращает конфигурацию |
| GET /api/signatures/{id}/image | Сохранённый PNG |
| GET /api/signatures/{id}/source | Исходный PDF/JPG/PNG для подписи из скана; для готового PNG без скана — 404 |

name содержит 1–120 символов после удаления внешних пробелов; если поле при загрузке PNG отсутствует, используется имя файла без расширения. signer необязателен, не более 120 символов; пустая строка становится null. Управляющие символы в названиях запрещены. width_mm — 10–100 мм, по умолчанию 70.

Готовая подпись должна быть неподвижным PNG: каждая сторона 16–8192 пикселя, площадь не более 16 мегапикселей, отношение высоты к ширине `aspect` от 0,025 до 4. Размер файла ограничен меньшим из MAX_UPLOAD_MB и 8 МБ. Полное декодирование выполняется в отдельном процессе через общий ограничитель PDF-операций. Ошибочный PNG или занятая очередь сохраняют прежнюю библиотеку и активный элемент.

Элемент signature содержит id (32 шестнадцатеричных символа), name, signer, width_mm, aspect, created (Unix time), sha256 готового PNG и size в байтах. Библиотека хранится отдельно от печатей: приватные data/signatures/{id}.png и UTF-8 data/signatures.json. Допускается не более 100 подписей. Выбор подписи не меняет библиотеку печатей, исходные PNG или документы.

GET /api/config дополнительно возвращает signature_ready, active_signature_id, active_signature_name, signature_aspect и signature_width_mm. При пустой библиотеке готовность false, идентификатор/название/пропорции null, ширина 70.

## Подпись из скана

Используются общие защищённые /api/stamp-sources: загрузка PDF/JPG/PNG, список, страницы и приватный оригинал. GET /api/stamp-sources возвращает `{items:[source]}`. Индексы страниц начинаются с нуля; crop задаётся в долях отображаемой страницы после учёта поворота PDF или EXIF изображения. Пример сохранения:

```json
{
  "page": 0,
  "crop": {"x": 0.20, "y": 0.65, "width": 0.60, "height": 0.15},
  "color": "dark",
  "strength": 50,
  "rotation": 0,
  "name": "Подпись руководителя",
  "signer": "Иван Иванов",
  "width_mm": 70
}
```

POST /api/stamp-sources/{id}/extract с page/crop/color/strength/rotation возвращает прозрачный PNG предпросмотра, не меняя ни одну библиотеку. Отдельный параметр вида изображения для предпросмотра не требуется. color — blue, red или dark; strength — целое число 0–100, rotation — конечное число градусов от −15 до 15. Выделение целиком находится внутри страницы и имеет положительную ширину/высоту.

POST /api/stamp-sources/{id}/save-signature принимает этот же набор плюс name, необязательный signer и width_mm. Сервер повторяет извлечение из постоянного оригинала и проверяет профиль подписи перед публикацией. Широкий PNG может подходить для подписи, хотя не проходит профиль круглой печати. Ответ — библиотека `{items,active_id}`. Переданный предпросмотр или его хеш не заменяет повторное извлечение.

Сохранённая подпись дополнительно содержит source_id, source_sha256, output_sha256, extraction (заданные параметры), extraction_result (размеры, покрытие, предупреждения и данные движка) и source_url с учётом APP_BASE_PATH. sha256 и output_sha256 совпадают для извлечённого готового PNG. GET /api/signatures/{id}/source возвращает неизменённый оригинал; исходный скан остаётся приватным. RGB полностью прозрачных пикселей очищаются, чтобы удалённый текст не сохранялся скрытым в готовом PNG; видимые и частично прозрачные пиксели сохраняются.

DELETE /api/stamp-sources/{id} разрешён только для неиспользованного источника. Ответ 409, если источник обрабатывается или связан с сохранённой печатью либо подписью. Закрытие диалога не удаляет оригинал.

## Привязка к документу

POST /api/documents принимает PDF/JPG/PNG и без готовой печати. Исходник сохраняется, изображения преобразуются в рабочий PDF, страницы анализируются как прежде. При наличии печати документ получает её отдельный снимок stamp.png. При наличии активной подписи копируется отдельный неизменяемый signature-{id}.png; подпись изначально выключена и не имеет координат. Её положение задаётся вручную.

Манифест дополнительно содержит:

- stamp_ready — фактическое наличие снимка печати; stamp_enabled — последнее намерение включения;
- signature_id, signature_name, signature_aspect, signature_width_mm, signature_ready;
- signature_enabled — изначально false; signature_placement — изначально null;
- signature_snapshots — метаданные сохранённых снимков по идентификатору библиотеки, включая фактический sha256.

Для старых манифестов значения по умолчанию добавляются только в ответе чтения. Файл при GET не переписывается, активная подпись из библиотеки к старому документу автоматически не привязывается.

POST /api/documents/{id}/signature принимает обязательное поле `{"signature_id":"32hex"}` либо `{"signature_id":null}` и возвращает манифест. Первый вариант явно выбирает снимок подписи для этого документа, второй снимает привязку. Новая привязка выключает подпись и сбрасывает её положение. Повтор той же действующей привязки сохраняет положение и флаг. Уже созданный снимок данного элемента используется повторно без перезаписи; смена глобальной активной подписи не меняет прежние документы. Старые снимки и результаты остаются в документе после смены или снятия привязки.

GET /api/documents/{id}/signature.png возвращает выбранный снимок, либо 404 при отсутствии привязки. Во время обработки документа изменение привязки отвечает 409.

## Итоговый PDF

POST /api/documents/{id}/compose и POST /api/documents/{id}/compose-scan принимают:

```json
{
  "placement": {"page": 0, "x": 340, "y": 500, "width": 113.38582677, "height": 113.38582677},
  "signature_placement": {"page": 1, "x": 250, "y": 500, "width": 198.42519685, "height": 39.68503937},
  "profile": "standard",
  "dpi": 150
}
```

placement относится к печати, signature_placement — к подписи. Любое из полей можно передать null или опустить, но нужно минимум одно изображение. Это явный выбор для текущего результата, независимо от прошлых флагов. Изображения могут находиться на разных страницах. Координаты x/y и width/height — пункты отображаемой страницы (72 пункта = 25,4 мм), с учётом её CropBox и Rotate. Координаты неотрицательны, изображение целиком внутри страницы, пропорции сохраняются. Ширина печати 20–60 мм, подписи 10–100 мм. Недостающий снимок отвечает 409.

Сборка выполняется один раз от исходного рабочего PDF. Обычный результат сохраняет исходные страницы, текст, размеры и повороты; добавляет фактические PNG снимков. compose-scan затем растеризует весь собранный документ, включая страницы без изображений, создавая PDF с имитацией сканирования. profile — light/standard/strong, dpi для сканирования — строго целое 150 или 200. Для обычной сборки параметры качества не используются.

Ответ — application/pdf, с Content-Disposition и заголовками X-Result-Id / X-Result-Url. Каждая успешная операция создаёт отдельный неизменяемый файл. Он доступен через GET /api/documents/{id}/results/{result_id}; прежние версии не заменяются.

Запись results содержит id, kind (`composed` либо `scan`), filename, created, url с APP_BASE_PATH, size, sha256 фактического итогового PDF, source_sha256, stamp_enabled/signature_enabled, placement/signature_placement для реально включённых изображений, stamp_id/name/sha256 и signature_id/name/sha256. Поля выключенного изображения равны null. overlays содержит по каждому включённому изображению kind, id, name, placement, image_sha256 из фактически вставленных байтов. У скана также есть profile, dpi, simulated_scan, scan (метаданные финального сканирования) и composed_sha256 промежуточного обычного PDF. Итоговый sha256 относится к скачиваемому файлу.

Манифест сохраняет последние флаги включения и последние переданные координаты. Выключение изображения не стирает его прежнюю позицию; это позволяет восстановить ручное размещение. Новая привязка подписи сбрасывает её позицию. Старые /stamp и /scan остаются операциями только с печатью и не включают подпись.

## Ресурсы и ошибки

Парсинг PNG/PDF, извлечение, сборка и имитация скана выполняются в отдельном процессе через общий slot с лимитами времени и размера. Обычная сборка резервирует 2 × MAX_RESULT_MB под временный и итоговый файлы движка; сборка со сканом — 3 × MAX_RESULT_MB под промежуточный PDF и временный/итоговый скан. Каждый отдельный файл контролируется по MAX_RESULT_MB. Каждая операция использует собственную временную папку; родитель удаляет её после успеха, ошибки или остановки worker.

Все библиотеки, оригиналы, снимки и результаты учитываются в общей MAX_TOTAL_MB. История не имеет TTL. Заполнение квоты блокирует новую операцию, сохраняя прежние данные. Ошибка публикации удаляет только новый незавершённый результат; манифест, библиотека и прежние файлы сохраняются. Перед публикацией сборки сверяются итоговый PDF SHA и SHA выбранных снимков с сохранённой историей; изменение снимка вне сервиса вызывает 409.

Ответы: 401 — нет действующей сессии, 403 — CSRF/источник запроса, 404 — элемент не найден, 409 — занятый документ/источник или отсутствующий/изменённый снимок, 413 — размер, 422 — формат/параметры/подписанный PDF, 429 — квота/очередь, 503 — общая авторизация недоступна, 507 — ошибка записи.
